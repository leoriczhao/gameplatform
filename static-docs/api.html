训练闭环入口

主路径：OpenEnv 采样 → SDK 导出 ONNX → 模型托管 → PvE / PvP / 模型对战 → 积分。下方为接口分类总览；侧栏可跳到鉴权、环境、模型等章节。

  1. ① OpenEnv
  2. ② SDK 导出
  3. ③ 上传托管
  4. ④ 游玩验证
  5. ⑤ 对战积分

交互式契约：Swagger UI · OpenAPI schema · Base URL https://games.cree1p.com

多游戏 RL 平台：每个游戏提供官方 OpenEnv 环境交互（WS 会话，训练算法在客户端、环境在后端）与前端界面（人工 / 内置 AI 演示 / 模型）。注册账号后可用会话制对战（PvE / 人 vs 人 PvP）、ONNX 模型托管与模型对战。Base URL：https://games.cree1p.com，业务 HTTP 与环境 WS 均使用 JSON。本文描述当前契约，不代表本次变更已部署或完成验收。平台业务交互式文档见 Swagger UI 与 OpenAPI schema。

接口分类总览

类别接口鉴权说明
① 平台级GET /api/games · GET /api/health无游戏目录（含每游戏元数据）、健康检查
② 环境交互（唯一入口）/api/openenv/{game} · WS /ws无官方 OpenEnv 0.4.1，一连接一实例；reset/step/state，每游戏共享并发上限 64
③ AI 与排行榜POST /api/{game}/ai/action · GET /api/{game}/scores无内置 AI 咨询、只读排行榜；合格成绩由服务端结算

⑤ 对局 v2/api/v2/matches · /api/v2/{game}/matchmaking/*创建和操作需登录；读取按可见性控制统一练习、PvP、模型对战、观战和帧回放；命令走 REST，事件走 SSE
⑥ 模型托管 v1POST/GET/DELETE /api/v1/models/*Bearer（用户）上传 ONNX → 契约校验 → PvE 对手 / 模型代打 / 模型对战
⑦ 记录与积分GET /api/v1/matches · GET /api/v1/ratings/{game}Bearer（用户）保留的只读对局记录与 ELO 积分榜；新对局由 v2 创建

闭环：② OpenEnv 采样 + 客户端训练 → SDK 导出 ONNX → ⑥ 上传托管 → ⑤/⑦ PvE、PvP、模型对战 → ⑦ 积分。② 与 ⑤ 背后是同一套游戏引擎（同一 step_state），当前游戏在固定版本、相同 seed/options 与动作输入下重建相同轨迹。

账号与鉴权 v1

密码 bcrypt(cost 12) 存储；登录/注册返回 JWT（HS256）。需要鉴权的接口带请求头 Authorization: Bearer <token>。用户名 3-24 字符，密码 8-128 字符。

POST /api/v1/auth/register 注册（自动登录）

{"username":"alice","password":"password123"}
→ {"token":"eyJ…","user":{"id":1,"username":"alice","nickname":"alice","role":"user","status":"active"}}

POST /api/v1/auth/login

{"username":"alice","password":"password123"} → {"token":"eyJ…","user":{…}}
401 {"detail":"用户名或密码错误"}

POST /api/v1/auth/guest 游客身份

游客身份：返回一个每浏览器唯一的游客 JWT（sub=guest-<uuid>），用于浏览、观战与限流配额区分（创建游玩会话需要登录账号）。共享 NAT 下各浏览器互不冲突。

POST /api/v1/auth/guest → {"token":"eyJ…","user":{"id":null,"username":"guest-…","role":"guest"}}

GET /api/v1/auth/me

Authorization: Bearer <token> → {"user":{…}}    # 游客 token 返回 401

游戏接入 GDK（v2，13 G3 后统一为游戏包）

接入新游戏 = 打一个游戏包（zip：game.yaml 声明 + __init__.py 暴露 get_adapter() + 可选只读资源）。平台在沙箱中运行它，并自动获得 OpenEnv 环境入口、AI 咨询、榜单、大厅卡片、会话制游玩（PvE/PvP）、模型托管——官方种子游戏（snake/tetris/microrts）与用户上传走完全同一条管线。包规范 v2 与完整步骤（模型契约、渲染、控件）见 docs/design/12/13 与 gdk-ug/。

  __init__.py   # def get_adapter() -> EnvAdapter（info/new_state/step_state/validate_*/obs/ai_action…）
  weights.npz   # （可选）只读资源，.npz/.npy/.bin
# 本地自测：python gdk-ug/test_runner.py my-game

成长与排行 v1.0-c（XP/等级/统计/周榜）

数值见 docs/design/08-成长与赛事数值.md：PvP 对局结束 +10 XP、胜者额外 +15；PvE 完成 +5（胜利再 +5）；等级曲线 xp(n) = 50·n·(n-1)（L2=100）。每次 ELO 结算落 rating_history 一行供走势图。周榜 = 最近 7 天按胜场数聚合。

统一对局 v2（服务器权威）

练习、PvP、模型对战、观战和回放共用 Match。创建和操作需要登录；客户端提交命令，服务端维护状态并通过 SSE 发布变化。旧 v1 游玩会话、房间、匹配和回放 API 已删除，旧客户端不会自动兼容。

对局创建时即获得字符串 id 并写入记录；主要状态为 waiting、active、finished、cancelled、aborted。进行中的状态与匹配队列在内存中；结束后的帧由服务端封存。

POST /api/v2/matches 创建对局

Authorization: Bearer <token>
{"game":"snake","mode":"practice","visibility":"unlisted","settings":{"seed":42}}
→ 201 MatchView，例如 {"id":"a1b2c3d4e5f6","game":"snake","status":"active",…}

请求字段为 game、可选 seats、mode、visibility 和 settings.seed。省略座位时使用游戏默认座位与对手；指定 seed 的练习局可复现，但不会进入分数榜。

MatchView 包含 id/game/version/kind/mode/visibility/status/result/seats/you/tick/frame/to_act/deadline_at/frames/chat/seq。you.seat 是当前玩家的座位；观战者为 null。id 贯穿对局与回放，不是 v1 数字记录 id。

PvP 房间与快速匹配

POST /api/v2/matches
{"game":"microrts","mode":"casual","visibility":"private",
 "seats":[{"seat":"p0","occupant":"me","controller":{"type":"human"}},
          {"seat":"p1","occupant":null,"controller":{"type":"human"}}]}
→ 201 MatchView，房主可从 invite 取得邀请码

GET  /api/v2/matches?game=microrts&mode=casual      # 等待中的公开房间
POST /api/v2/matches/{id}/seats/p1/join {"invite":"OD2ZX4"}  # 私有房需要邀请码
GET  /api/v2/me/matches                             # 我的 waiting / active 对局

人类对战支持 casual 和 ranked；公开房间进入大厅，unlisted 凭链接读取，private 只允许座位玩家读取并要求邀请码入座。对局结束后，ranked 人类对战结算 ELO。重连使用同一对局 id、快照与事件流。

POST   /api/v2/microrts/matchmaking/queue {"mode":"ranked"}
GET    /api/v2/microrts/matchmaking/status
DELETE /api/v2/microrts/matchmaking/queue
状态示例：{"queued":false,"matched":true,"mode":"ranked",
           "position":null,"wait_seconds":2,"match_id":"a1b2c3d4e5f6"}

匹配成功后使用 match_id 打开对局；成功结果可重复读取，队列在服务重启后失效。

快照、动作与事件流

GET  /api/v2/matches/{id}                    # MatchView 快照
POST /api/v2/matches/{id}/actions {"tick":0,"action":1}
→ 202 {"accepted":true,"seq":3}
GET  /api/v2/matches/{id}/stream             # text/event-stream
POST /api/v2/matches/{id}/controller {"seat":"p0","controller":{"type":"human"}}
POST /api/v2/matches/{id}/resign
POST /api/v2/matches/{id}/rematch

tick 为必填，必须与当前快照一致；同一座位在该 tick 尚未结算时再次提交会覆盖待提交动作，过期 tick 返回 409。202 只确认接收，最新状态从快照或 SSE 获取。练习局可切换自己座位的控制器；已结束的人类 PvP 可由双方发起并接受再来一局。

SSE 首次连接返回快照，后续发送 tick、seat、status、chat 等事件；可用 Last-Event-ID 或 ?since= 续传，日志不足时重新发送快照。服务端定期发送 ping；聊天内容仅发给座位玩家。

观战与回放

前端统一使用 /m/{id} 展示对局、观战与回放。公开或 unlisted 对局可凭 id 读取；private 对局仅玩家可读取。进行中的帧按观看者视角裁剪，终局后按权限读取封存帧。

GET /api/v2/matches/{id}/frames?from=0&limit=1
→ {"frames":[{"tick":0,"frame":{…},"actions":null,"events":[]}],
   "next":1,"total":2}

from 是帧数组偏移而非 tick；limit 为 1–500，最后一页 next=null。浏览器直接展示封存帧，不通过 OpenEnv 重新执行动作；无法重建或未封存的旧记录可能没有帧。

模型托管 v1（ONNX）

只接受 ONNX（onnxruntime CPU 推理）。上传时服务端校验：≤20MB、能加载、输入/输出 shape 匹配该游戏的标准契约；每游戏最多保留 5 个活跃模型。SDK 的 export_onnx 保证导出即合规。

契约游戏输入输出推理语义
game.snakesnakefloat32[1,1334] rotwin R=10 观测float32[1,3] Q 值simple：obs→argmax
game.tetristetrisfloat32[1,2,20,10] 双通道棋盘float32[1,4] Q 值simple：obs→argmax
game.micrortsmicrortsfloat32[1,1546] 6×16×16 网格 + 10 维单位特征float32[1,140] cmd×dir×type logitscomposite：model_inputs 逐单位 → 批量 run → model_decode（mask 后 argmax）

POST /api/v1/models 上传

multipart/form-data:  file=<.onnx>  game=microrts  name=我的DQN
Authorization: Bearer <token>
→ {"model":{"id":3,"owner_id":1,"game":"microrts","name":"我的DQN",
            "model_type":"onnx","io_contract":"game.microrts","meta":{},
            "status":"active","created_at":1.7e9}}
400 {"detail":"输入 shape 不匹配：期望 (1,1546)（game.microrts），实际 (1,256)"}

GET /api/v1/models/{id}

DELETE /api/v1/models/{id}

POST /api/v1/models/{id}/eval 标准评估

服务端跑 3 局（snake/tetris 记分；microrts 打内置 AI 记胜率），返回指标：

→ {"model_id":3,"metrics":{"games":3,"avg_score":…,"avg_length":…,

模型对战、记录与积分

POST /api/v2/matches 创建模型对战

{"game":"microrts","seats":[
  {"seat":"p0","occupant":null,"controller":{"type":"model","model_id":3}},
  {"seat":"p1","occupant":null,"controller":{"type":"ai","strategy":"light_rush"}}
]}
→ 201 MatchView，id 为对局 uid

支持两个模型座位，或模型对内置 AI；无人占座时至少一个模型属于创建者。通过 GET /api/v2/matches/{id} 或 SSE 观察结果，通过 /frames 获取帧回放。

GET /api/v1/matches 我的对局

保留的只读记录列表，按参与玩家筛选，可包含进行中的对局；新记录包含通往舞台的 uid。进行中的可重连对局可另用 GET /api/v2/me/matches 查询。

GET /api/v1/matches/{id} 只读记录详情

按数字记录 id 查询并返回 {"match":…}；新对局与可迁移的历史记录带有字符串 uid。对局状态和帧回放请使用 v2 接口。

GET /api/v1/ratings/{game} ELO 积分榜

→ {"items":[{"user_id":1,"rating":1216.0,"games":1,"wins":1,"name":"bob"},…]}

仅人 vs 人 PvP 结算：ELO K=32、起始 1200，平局各半。模型对战不计分。

环境交互（唯一官方 OpenEnv 入口）

远程环境基址为 /api/openenv/{game}，目录 GET /api/games 提供 openenv_url 与 schema_url。远程交互使用官方 openenv==0.4.1 栈；旧环境 API 已删除。平台对局使用独立的 v2 Match API。完整环境说明见仓库 docs/api/openenv.md。

WS 一连接一实例：官方 GenericEnvClient.reset/step/state 在同一连接操作服务端环境。远程环境计算在后端；SDK 的 LocalVecEnv 则可下载游戏包后在本地进程运行。两者使用相同游戏包规则。

生命周期与容量：当前每游戏最多 64 个并发环境，所有客户端共享，不是吞吐保证。关闭连接销毁会话。超时或断线后不要盲目重发 step（先前动作可能已执行）；当前无断线续局，重连后显式 reset。成功、错误和取消路径均应关闭连接。

官方 OpenEnv 协议（0.4.1）

每游戏挂载官方 create_fastapi_app 子应用（backend/openenv_native.py），不是与旧环境 API 并行的兼容面。全局环境目录为 GET /api/openenv/list_environments。

reset：固定版本与整局配置

{"type":"reset","data":{"seed":42,"version":"1.0.0","options":{},
                        "obs_mode":"state","rewards":{},"include_state":true}}
  • seed 为非负整数，默认 0；options 由游戏定义。
  • version 省略时使用当前发布版本；显式指定必须是仍可用的已审核包。reset 固定本局版本，发布/回滚不让进行中的局面换动力学；下架/暂停仍使会话不可用。SDK 默认持续钉住初始化时读取的版本。
  • obs_mode 缺省为首个服务端观测模式；显式 state 请求当前适配器完整状态，其他值必须由游戏声明。
  • rewards 只覆盖已声明奖励键，在整局内固定；值必须有限且绝对值不超过 1000。
  • include_state 默认 false，true 时张量观测也附带完整 state；非法配置明确报错。

step 与 observation

{"type":"step","data":{"value":1}}
→ {"type":"observation","data":{"observation":{…},"reward":0.0,"done":false,…}}

value 是游戏原始动作（整数、命令列表或复合对象），不含调用方注入的局面。reset/step 均返回官方 observation 响应，其中 observation 为：

# 张量观测；include_state=true 时 state 为完整局面
{"type":"tensor","data":[…],"shape":[…],"dtype":"float32","state":null,"metadata":{…}}
# 状态观测
{"type":"state","state":{…},"metadata":{…}}

reset 的 observation.metadata.environment 包含 game/name/actions/obs_modes/schemas/meta/version/max_concurrent_envs 等描述，step 不重复整份描述。完整状态是当前快照型适配器的能力，不要求所有未来游戏的策略观测公开内部状态。环境本身在 done 后不会自动 reset。

state 与对局回放

{"type":"state"}
→ {"type":"state","data":{"episode_id":null,"step_count":0,"game_state":null,
    "environment":{"game":"tetris","version":"1.0.0","max_concurrent_envs":64,…}}}

reset 前 game_state=null，environment 描述当前版本；reset 后是本局状态与固定版本的 environment.schemas/meta。HTTP /schema 仅描述当前发布版本，不可替代历史包配置。

平台对局回放直接读取 GET /api/v2/matches/{id}/frames 的服务端帧，不需要连接 OpenEnv 逐步重算。旧记录迁移可能需要原游戏版本和初始化数据；无法迁移的记录可能没有帧。

游戏：贪吃蛇 snake

20×20 网格。与 snake.cree1p.com 的环境逐位一致（同 seed 同轨迹）。

state 字段说明
body蛇身格子 [[x,y],…]，body[0] 是蛇头，至少 2 格
direction绝对朝向 0=上 1=下 2=左 3=右
food[x,y] 或 null
score / tick / _seed / done / cause / gridcause: wall|self|win|null；进行中的对局视角会隐藏私有字段
  • 动作（相对朝向）：0=左转 1=直行 2=右转（180° 掉头不存在）
  • 奖励：{"food":1.0,"step":-0.01,"death":-1.0}（可覆盖）；吃豆 score+1，食物由 (seed, tick) 确定性生成
  • obs（服务端）：grid = 3×22×22 补边网格（ch0 危险=墙+蛇身含头，ch1 蛇头，ch2 食物）；模型契约用 rotwin (1,1334)

游戏：俄罗斯方块 tetris

10×20 棋盘，7 种方块，7-bag 出块（由 (seed, bag_idx) 确定性生成，同 seed 同轨迹）。

state 字段说明
board20×10 整数矩阵：0=空，1..7=已锁定的方块 id+1
piece{"id":0..6,"rot":0..3,"x":int,"y":int}，当前活动方块
next下一块 id（0=I 1=O 2=T 3=S 4=Z 5=J 6=L）
bag / bag_pos / bag_idx7-bag 状态（当前适配器的状态快照；OpenEnv 会话在服务端持有局面）
score / lines / tick / _seed / done / cause / gridcause: lockout|null；进行中的对局视角会隐藏私有字段
  • 动作：0=左移 1=右移 2=顺时针旋转（带基础踢墙） 3=硬降
  • 自由动作语义：左/右/旋转不推进 tick、奖励恒 0；只有硬降推进 tick、锁块、消行
  • 奖励：{"line":1.0,"step":-0.01,"death":-1.0}；硬降时 reward = step + k²·line (+ death)，k=本次消行数；方块出生即碰撞 → 游戏结束（lockout）
  • obs（服务端）：grid = 2×20×10（ch0 已锁方块 0/1，ch1 活动方块 0/1）——即模型契约输入

游戏：微RTS microrts

16×16 微型 RTS（MicroRTS 规则移植）：采矿 → 建造兵营 → 爆兵 → 摧毁敌方全部单位。

state 字段说明
terrain16×16：0=空地 1=墙 2=金矿（由 seed 确定性生成：8 矿 4 墙）
units双方单位数组：{id, owner(0|1), type, x, y, hp, carry, cd, busy}；type: base/barracks/worker/light/heavy/ranged
bank[我方金币, 敌方金币]（初始各 5 金，MicroRTS 标准）
damage[我方累计伤害, 敌方累计伤害]（时间到按此判胜负）
tick / seed / time_limit / done / winner / causetime_limit 4000；cause: eliminated|time
opponentworker_rush|light_rush|ranged_rush|external（模式开关，见下）

指令（复合动作）

[[unit_id, cmd, dir?, type?], …]     # 每个 tick 每个空闲单位一条指令
cmd: 0=wait 1=move(dir) 2=harvest(dir) 3=return(dir) 4=build(dir,type)
     5=produce(dir,type) 6=attack(dir)   dir: 0=N 1=E 2=S 3=W
单位/属性：base hp10 → 产工人(1金,50t)；worker hp1 攻1 → 采/回/建兵营(5金,100t)
           barracks hp4 → 轻骑(2金,80t) 重骑(3金,120t) 射手(2金,100t)
            轻骑 hp4 攻2 · 重骑 hp10 攻4 · 射手 hp2 攻1 射程3 · 攻速冷却 4t
胜负：摧毁对方全部单位；4000 tick 内未分胜负按伤害判定（平局 winner=null）

两种对战模式（由 OpenEnv reset 的 options.opponent 决定）

  • 单代理 vs 内置策略（默认）：opponent ∈ {worker_rush, light_rush, ranged_rush}——对方策略在服务端环境内部运行，API 动作只需提交己方（p0）的指令列表（与 snake/tetris 同构，SDK 零改动）
  • 双代理 external：opponent = "external"——API 动作为 {"p0": [cmds], "p1": [cmds]}，双方都由调用方控制（人机/机机对战，训练自对弈）。游玩会话（PvE/PvP）即此模式的服务端封装
  • obs（服务端）：grid = 6×16×16 通道（墙/金矿/我方单位/敌方单位/我方建筑/敌方建筑）
  • 奖励：{"win":1.0,"loss":-1.0,"damage":0.01}；每 tick reward = 本 tick 实际伤害×damage，终局 + win/loss（p0 视角）
  • 示例：连接 /api/openenv/microrts 的 GenericEnvClient，env.reset(seed=42, options={"opponent":"light_rush"}) 后，在同一连接 env.step({"value":[[0,5,1,"worker"]]}) 让基地向东产工人

外部 bot 控制器

创建对局时可为座位指定 {"type":"bot","url":"http://…"}。由平台服务端向该地址发送状态并读取动作；地址必须能从服务端访问，接受 HTTP 或 HTTPS。

方向载荷
平台 → bot{"state": {…},"seat":"p0"}；seat 随控制的座位变化
bot → 平台JSON {"action":…}，也可直接返回游戏动作；具体结构由游戏定义

这不是浏览器直接调用：bot 响应不依赖浏览器 CORS。可通过 SessionClient.start_pve(opponent={"type":"bot","url":"…"}) 为双座练习局指定 bot 对手。

本地游戏包训练

LocalVecEnv 首次使用时下载指定游戏包并校验 sha256，之后在本地进程执行环境。官方包可直接使用；UGC 包需作者开放本地训练，使用者还需显式设置 trust_remote_code=True。

from gameplatform import LocalVecEnv

with LocalVecEnv(game="snake", n=4, obs_mode="rotwin",
                 base_url="http://127.0.0.1:8080") as envs:
    obs = envs.reset(seed=42)
    obs, rewards, dones, infos = envs.step([1] * 4)

远程训练（OpenEnv + Gymnasium 包装）

RemoteVecEnv 每槽管理一条独立 OpenEnv 连接，不使用单 HTTP 请求批量推进。seed 推进、自动重开和终止观测由 SDK 管理；每游戏 64 个远程环境额度由全部客户端共享。

from gameplatform import RemoteVecEnv            # 每个环境独立连接
envs = RemoteVecEnv(game="tetris", n=16, obs_mode="grid",
                    base_url="http://127.0.0.1:8080")
try:
    obs = envs.reset()                            # grid/state；snake 特征也可在 SDK 从状态计算
    obs, rewards, dones, infos = envs.step([3] * 16)
finally:
    envs.close()

import gameplatform.gym                           # 注册 platform-snake-v0 / platform-tetris-v0
import gymnasium as gym
from stable_baselines3 import PPO
with gym.make("platform-tetris-v0", obs_mode="grid", base_url="http://127.0.0.1:8080") as env:
    model = PPO("MlpPolicy", env).learn(total_timesteps=100_000)  # 算法在本地，环境在后端

gym 封装只注册 snake/tetris（离散动作）。复合动作游戏（microrts）请直接用 RemoteVecEnv 传指令列表，或按模型契约导出 ONNX。
