系统分层

平台围绕三个核心能力：玩游戏（网页/会话制对局）、训模型（官方 OpenEnv 会话，训练算法在调用方运行）、打对抗（上传 ONNX 模型自动参战）。当前游戏运行层仍是现有 EnvAdapter：网页、训练、模型对战共用规则。确定性重放限定于固定版本、相同 seed/options 与动作输入，不表示任意复杂外部游戏引擎已支持。

一引擎原则 · D3

游戏动力学只有一份

网页会话、OpenEnv 环境和模型对战 worker 调用同一个 step_state——不存在「训练一套、线上另一套」。

一连接一实例

WS 会话持有局面；SDK 向量槽各用独立连接，不再单 HTTP 批量推进。关闭连接销毁实例，重连后显式 reset，不能盲目重发 step。

D26 · 游戏解耦

平台零游戏名硬编码

官方种子游戏与用户上传走同一条沙箱管线（game.yaml + __init__.py），import 即注册。

D18/D25 · 沙箱

受限子进程隔离

纯函数 JSON 协议 + rlimit + AST 静态扫描 + 审核兜底；作者只能用标准库白名单 + numpy。

一引擎 · 业务与环境分离

核心是游戏包的 EnvAdapter 纯函数契约。平台复用此契约提供对局会话、AI/排行榜业务、官方 OpenEnv 环境与模型对战 worker；训练只通过 OpenEnv 交互，不再有另一套环境协议。

适配器复用的边界

  • 契约面向「游戏动力学」而非任何传输协议：不要求 HTTP、不要求 Gymnasium、不要求 OpenEnv 概念。
  • OpenEnv server 将 reset/step/state 映射到现有 new_state/step_state 与会话状态，描述由 info() 和版本元数据提供。
  • 完整 state 是当前快照型适配器的能力；未来游戏的策略观测不必公开内部状态，外部引擎仍需适配与验证。

游戏包 v2 契约

一个游戏 = 一个 zip 包（官方种子包 packaged-games/* 与用户上传走同一条沙箱管线）。结构：game.yaml（元数据 + PvP 能力声明）+ __init__.py（鸭子类型 EnvAdapter）+ 资源文件。本地自测用 gdk-ug/test_runner.py（与线上沙箱同一套加载与校验逻辑）。

训练闭环

训练算法在调用方本地运行；服务器只做环境转移。SDK 用官方 OpenEnv 连接包装为标准 Gymnasium 接口；向量槽各有独立连接，不再单 HTTP 批量推进，不承诺旧吞吐。

观测模式：服务端（grid 张量，obs_mode 参数）或客户端从 raw state 计算 （snake 的 features / rotwin / reach，sdk/gameplatform/games/snake_features.py）。
奖励覆盖（OpenEnv reset）：rewards 只接受游戏声明键，整局固定； 数值必须有限且绝对值不超过 1000，非法配置明确报错。

对局闭环

对战按游戏归属（D27）：大厅卡片 / 游戏页直入该游戏 PvP 页。房间（公开/私有 · ranked/casual）+ 快速匹配（ELO band 撮合）+ 断线重连 + 再来一局 + 观战 + 回放 + 分享链接。

D9 · 撮合

ELO band + 时间放宽

初始 ±100，每 5s 放宽 +100，上限 ±400，60s 后任意匹配——Lichess 式，简单可解释。

D10/D11

ranked / casual 双轨

好友私房默认 casual（防刷分）；模型独立 model_ratings 表（起始 1200，K=32），与人分榜隔离。

D12

内存态队列

会话/房间/匹配队列进程内态（重启失效）；SQLite 持久化对局结果与回放。

D3 延伸

观战/回放逐位一致

回放记录仍走平台 API；OpenEnv 按历史 version + seed/options reset，逐条 step 记录动作。渲染读会话 environment.schemas/meta，结束/错误/取消都关闭连接；PvE 记录实际对手动作。

UGC 管线

任何注册用户可上传游戏包（草稿 ≤5 / 公开 ≤3），管理员审核通过才公开；官方种子游戏与用户上传同一条沙箱管线（D26）。

为什么 UGC 游戏自动获得 OpenEnv 面

  • OpenEnv 复用现有 ProxyAdapter（沙箱 worker 转发），游戏包继续实现 EnvAdapter；旧环境路由已删除。
  • 契约方法 info/new_state/step_state/validate_* 已覆盖 OpenEnv server 的 schema/reset/step 需求；obs 缺失时观测自动回退 {"type":"state","state":…} 透传。
  • 沙箱内不需要安装任何新库（D25：标准库白名单 + numpy 不变）。

OpenEnv：唯一环境交互入口

使用官方 openenv==0.4.1 的 create_fastapi_app 子应用与 PlatformEnvironment（backend/openenv_native.py）。每条 WS 连接拥有一个环境实例；游戏执行继续复用现有 EnvAdapter 和沙箱。原来的「并行附加兼容面」决定仅留作历史，现行契约见 docs/api/openenv.md。

OpenEnv 概念当前契约边界
resetseed/version/options/obs_mode/rewards/include_stateseed 默认 0、非负；version 为可用已审核包，省略取当前版本；版本与奖励固定整局
step{"type":"step","data":{"value": <raw action>}}raw 为 int/list/dict，只提交游戏动作，不注入局面
observation官方 {type:"observation",data:{observation,reward,done,…}}内部为 tensor（data/shape/dtype/state/metadata）或 state（state/metadata）；include_state 默认 false
环境描述reset 的 observation.metadata.environmentgame/actions/obs_modes/schemas/meta/version/max_concurrent_envs；step 不重复整份描述
state{episode_id, step_count, game_state, environment}reset 前 game_state=null；reset 后 environment.schemas/meta 固定为本局版本，用于历史回放渲染
HTTP reset/step/state官方端点仍存在，每个请求都是临时实例HTTP reset 不为下次 step 留状态，无 state/action 注入信封；HTTP /schema 仅描述当前发布版本
WS 会话一连接一实例，每游戏共享上限 64容量非性能承诺；断线不续局，重连显式 reset，超时后不可盲目重发 step
任务集split=default，task 为 seed 序列（10,000 个）保留官方任务接口，不是环境批量推进
from openenv.core import GenericEnvClient

with GenericEnvClient(base_url="http://127.0.0.1:8080/api/openenv/tetris").sync() as env:
    info = env.state()["environment"]
    env.reset(seed=42, version=info["version"], obs_mode="state")
    result = env.step({"value": 3})
    print(result.reward, result.done, result.observation["state"])
观测与奖励：obs_mode 默认取服务端首个模式，显式 state 请求当前适配器完整状态，其他值须由游戏声明；include_state=true 时张量也附带完整状态。rewards 只覆盖声明键、必须有限且绝对值不超过 1000。非法配置明确报错，环境 done 后不会自动 reset。完整快照和确定性重放只覆盖当前适配器能力，不代表任意复杂外部游戏已支持。
MCP：沿用官方 openenv/session/* 会话机制与 describe/new_episode/observe/act；new_episode 支持同样的版本、观测和奖励配置。无论 WS/MCP，成功、错误、取消都应释放连接/会话。网页游客预览 reset 后即关闭；历史回放按原版本和 seed/options 重建，不用当前 /schema 渲染历史包。

历史架构决策（Decision Log 精选）

历史记录，不是当前环境契约。下表保留当时决定；D2 的无状态批处理与设计 15 的并行附加面已被 唯一官方 OpenEnv 契约取代，不保留旧环境 API。其他决策的现行边界见相应业务契约。
#决策选择
D1游玩 API 形态会话制（有状态 session）——多人对战需要服务端持有对局状态
D2训练 API 形态无状态批处理 env API——已验证的高吞吐模式，同 seed 可复现
D3一个引擎原则游玩/训练共用一个 EnvAdapter 规则内核——动力学完全一致
D4模型托管格式ONNX（v1）——跨框架标准、服务端推理无需 torch、镜像小
D9/D10/D11匹配与计分ELO band + 时间放宽；ranked/casual 双轨；模型独立积分表
D12队列/房间存储v1 内存态（单容器）——规模小，避免过早引入分布式组件
D14聊天与通知v1 轮询 + 落库（不引入 WebSocket）——改动面最小
D18/D25UGC 运行隔离/依赖受限子进程沙箱 + 标准库白名单 + numpy——rlimit/超时/熔断
D26游戏与平台的关系取消内置/UGC 区分——官方种子包走同一条沙箱管线，平台零游戏名硬编码
D27大厅/对战交互/arena 移除；对战按游戏 slug（/games/{slug}/pvp）；历史曾讨论磁贴条控制台（已废弃，见设计 14）
D28（15）OpenEnv 兼容层单独提供一套 wire 对齐接口（自实现 + HTTP/WS）——并行附加面，不迁移
