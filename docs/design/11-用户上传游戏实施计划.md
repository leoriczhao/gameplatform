  既有文件只做最小侵入（registry 动态注册/注销、admin 路由注册、main.py 挂载）；

## P2 · 沙箱 runner + ProxyAdapter（安全核心）

- [x] `backend/ugc_runner.py`：
  - worker 子进程（`subprocess.Popen`，`preexec_fn` 设 `setsid` + `resource.setrlimit`（AS 512MB/CPU/FSIZE/NPROC/NOFILE），
    工作目录只读；通信 newline-JSON over stdio；请求/响应带 id 关联；
  - runtime 白名单：`ugc_worker.py` 入口先装「禁用桩」（socket/subprocess/os.system/ctypes/文件写/目录外读 全抛错），
    再 import 用户包并暴露 `new_state`/`step_state`/`ai_action`/`validate_*`/`sample_action`/`score_bounds`；
  - 超时（默认 200ms）→ kill 进程组；连续 3 次失败 → unhealthy + 熔断回调；
  - **池化与重启**：每游戏一个长驻 worker（懒启动，空闲 10 分钟回收），崩溃自动重启（带退避），
    版本更新 = 换新 worker、旧版本会话用完即回收；
- [x] `backend/ugc_proxy.py`：ProxyAdapter（实现 EnvAdapter 全部方法，转发 IPC；本地缓存 info/score_bounds；
      `pvp_enabled` 能力标记 + 通用 `ai_request_model` pydantic 模型）；
- [x] `registry.py` 增 `unregister(game_id)`/`game_source()` 与「注册来源」标记（builtin|ugc）；
      顺手修复 registry 的循环导入（EnvAdapter 改 TYPE_CHECKING）；
      `main.py` 启动加载已公开 UGC → 随 P4 集成做（依赖 P3 的 ugc 表）；
- 验收：`tests/test_ugc_runner.py` **10 用例全绿**——正常包往返+确定性；socket/写文件被 runtime 拒绝；
  死循环 200ms 强杀且连续 3 次熔断（回调触发）；2.4GB 分配撞 512MB 限制返回 MemoryError；
  崩溃自动重启；空闲回收；ProxyAdapter 接口面；registry 来源/注销。全套 157 passed。

## 测试与验收总表

| 用例 | 期望 |
|---|---|
| 上传非法包（穿越/超限/二进制/坏 yaml） | 400，无落盘 |
| 上传恶意代码（socket/写文件/eval/死循环/爆内存） | 静态拒绝或 200ms/512MB kill，主服务无感 |
| 草稿→pending→published 状态机 | 各阶段可见性正确；旧 active 版本在审核期继续服务 |
| published 游戏全平台能力 | env/play/scores/ai/榜单/观战回放/模型契约 全通 |
| PvP（声明 pvp.enabled 的游戏） | 双账号 房间+快速匹配 全流程；ranked 结算 ELO、casual 不计；unit 与 choice 两种交互均可完赛 |
| 作者自行下架 | unpublish 后对玩家隐藏、回到 draft、可再次提交审核 |
| 熔断与封禁联动 | 超限 paused；封作者→游戏下架；举报→admin 处理 |
| 配额 | 草稿>5 / 公开>3 被拒 |

## 风险与演进路径

- **沙箱逃逸（进程级 rlimit 的固有残留）**：靠静态扫描+审核+熔断+禁二进制扩展兜底；
  若 UGC 规模扩大或出现恶意事件 → 将 runner 底层替换为 gVisor/Firecracker（**IPC 协议不变**，仅换容器实现）；
- **性能**：每游戏长驻 worker + 空闲回收；若游戏数 >50 → worker 池改为 LRU 淘汰 + 冷启动预热队列；
- **命名空间**：slug 全局唯一且不可与内置冲突；未来多用户同名诉求再引入 `@author/slug` 二级命名；
- **审核人力**：当前 admin 终审；若投稿量大 → 引入 BGA 式测试者批准/评分门槛（设计已预留）。
