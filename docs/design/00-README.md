## 核心设计决策（Decision Log）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 游玩 API 形态 | **会话制**（有状态 session） | 多人对战需要服务端持有对局状态；训练面保持无状态 env |
| D2 | 训练 API 形态 | **保持现状**：无状态批处理 env API | 已验证的高吞吐模式，同 seed 可复现，SDK 现成 |
| D3 | 一个引擎原则 | 会话制游玩与 env 训练共用同一 `EnvAdapter` 规则内核 | 保证网页玩法和训练动力学完全一致 |
| D4 | 模型托管格式 | **ONNX**（v1）；权重+预设架构（v2）；bot URL（保留） | 跨框架标准、服务端推理无需 torch、镜像小 |
| D5 | 账号方案 | 用户名+密码 + JWT；游客可玩 PvE | 低摩擦起步，排行榜/模型/对战需登录 |
| D6 | PvP 范围 | **v1** 邀请码人 vs 人 + 模型 vs 模型（已实现）；**v2** 升级为房间 + 快速匹配双轨（见 [06](./06-匹配机制与房间系统.md)，D6 修订） | v1 先跑通对战闭环；v2 对标权威平台补齐完整对战体验 |
| D7 | 数据存储 | SQLite（延续现有）；表扩展 users/models/matches/ratings | 规模小，运维简单；需要时迁移 Postgres |
| D8 | 前端 | 延续 React + antd（亮色）；旧 vanilla 页面迁移或删除 | 已有基础，避免再换框架 |
| D9 | 匹配撮合算法 | **ELO 分差 band + 时间放宽**（初始 ±100，每 5s +100，上限 ±400，60s 后任意） | Lichess 式，简单可解释；规模大了再上 TrueSkill |
| D10 | 计分区分 | 对局分 **ranked / casual**；好友私房默认 casual（防刷分），匹配池两者可选 | Lichess casual/rated 模式 |
| D11 | 模型积分 | 独立 `model_ratings` 表（起始 1200，K=32），与人分榜隔离 | Halite 式模型排位 |
| D12 | 队列/房间存储 | v1 **内存态**（单容器，与现会话一致）；多副本/Redis 属 v2 | 规模小，避免过早引入分布式组件 |
| D13 | 平台范围 | 按**完整平台**建设（蓝图模块 A-L 全部立项），v1.0 MVP 为下一个里程碑（蓝图 §6） | 用户反馈：要的是完整游戏平台，不只是匹配 |
| D14 | 聊天与通知 | v1 用**轮询 + 落库消息**（与现有 2s 轮询一致），不引入 WebSocket；SSE/WS 属 v2 | 改动面最小，规模扩大后再升级 |
| D15 | 新数据表 | 好友/聊天/通知/XP/成就/赛季/锦标赛/举报等继续用 SQLite；备份脚本随 v1.0 交付 | 延续 D7，运维简单 |
| D16 | 前端 UI 层（v1.0 后） | 从 antd 迁移到 **shadcn/ui + Tailwind + sonner + lucide-react**（亮色极简）；业务逻辑与 API 调用不变，规范见 `web/DESIGN.md`（**修订 D8**） | antd 遗留依赖重，设计系统统一到 Tailwind |
| D17 | UGC 上传形态 | Python 包（zip：EnvAdapter + game.yaml），官方 GDK 模板 + 本地测试器 | 与引擎契约一致，作者门槛低 |
| D18 | UGC 运行隔离 | **受限子进程沙箱**：纯函数 JSON 协议 + rlimit + 禁网络/文件 + 200ms/512MB + 熔断；静态 AST 扫描 + 审核兜底 | 进程级隔离匹配当前规模；预留 gVisor/Firecracker 演进 |
| D19 | UGC 发布流程 | 双轨：注册用户可传「草稿」，管理员审核通过才公开，可随时下架 | 对标 BGA 生命周期 + itch.io |
| D20 | UGC 作者门槛 | 所有注册用户即可上传草稿 | 最大化创作者池，公开由审核把关 |
| D21 | UGC 功能范围 | v1：PvE+榜单、内置 AI、ONNX 契约、观战/回放、**PvP 房间+快速匹配+ELO**；不含自定义图片/音效 | 2026-08 用户修订：v1 即支持 PvP（能力声明制） |
| D22 | UGC 渲染 | 通用 JSON 棋盘渲染器（palette/units 声明 + emoji/字符） | 零前端代码执行风险 |
| D23 | UGC 配额与熔断 | 草稿 ≤5/公开 ≤3 每人；包 ≤20MB；step 200ms/512MB；连续超限自动 paused | 数值随运营调整 |
| D24 | UGC 版本管理 | 版本号 + 变更日志，每次更新重审；旧 active 版本审核期继续服务 | 对标 BGA post-release |
| D25 | UGC 作者依赖环境 | 仅平台 venv 已有库（标准库白名单 + numpy）；不可自带第三方依赖/二进制扩展 | 沙箱环境固定，避免依赖管理失控 |
| D26 | 游戏与平台的关系 | **取消内置/UGC 区分（2026-08 用户拍板）**：自带游戏（snake/tetris/microrts）打包为官方种子游戏包，与用户上传走同一条沙箱管线；平台核心零游戏名硬编码；允许破坏性重构 | 一套机制、平台纯粹是运行时，详见 [12](./12-游戏完全解耦重构设计.md)/[13](./13-游戏完全解耦实施计划.md) |
| D28 | 棋盘渲染能力（2026-09 用户拍板） | **L1 声明式渲染 v2**：`game.yaml` 扩展 cell/background/layers/hud/events + palette/units 条目（sprite/vector/orient/anim/enter/owner/hp），Canvas 主渲染 + DOM 回退；服务端校验、前端当不可信数据 | 现通用渲染器只有 emoji+背景色，表现力不足；纯数据扩展不新增信任边界（**修订 D22**） |
| D29 | 游戏包资源（2026-09 用户拍板） | **L2 资源包**：PNG/WebP 精灵 + OGG/MP3/WAV 音效，魔数嗅探 + 尺寸/体积/数量上限 + 精确白名单路由 + 内容寻址缓存；音效默认静音 | 表现力需要真实素材；新增的是**内容审核面**而非代码执行面（**修订 D21「不含自定义图片/音效」**） |
| D30 | 自定义渲染器（2026-09 用户拍板） | **L3 沙箱渲染器**：作者 `renderer.js` 只在 opaque-origin iframe 的 blob Worker（OffscreenCanvas）内运行，CSP `connect-src 'none'` 断网，看门狗超时终止并降级；**默认关闭**，官方包自动开启、UGC 需管理员显式开启 | 过程式视觉的最后手段；把不可信代码关进无 DOM/无网络/无凭证的盒子里（**修订 D22**） |
| D27 | 大厅/对战交互（2026-08 用户拍板；以设计 14 为准） | **撤销独立对战中心 `/arena`（破坏性移除）**；对战按游戏归属 `/games/{slug}/pvp`（找对手/对局/排行榜三 Tab）；大厅卡片「对战」入口（仅 `pvp.enabled`）；模型挑战在 `/models`（及游戏页）；独立战绩页 `/records` | 对战与游戏同在，避免跨游戏控制台；详见 [14](./14-对战交互重构设计.md) |

> **脚注（D27）**：早期「游戏磁贴条 / 对战控制台」草案与线框 [`arena-wireframe.html`](./arena-wireframe.html) 已废弃；现网无 `/arena`，权威正文见设计 14。
