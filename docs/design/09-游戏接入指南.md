# 09 · 游戏接入指南（GDK，v2 游戏包）

> 状态：v2（13 G3 后统一为「游戏包」，2026-08）· 读者：想给平台接一个新游戏的开发者
> 配套：gdk-ug/template/（包骨架）、packaged-games/{snake,tetris,microrts}/（三个官方范例包）、
> gdk-ug/test_runner.py（本地自测）、设计 [12](./12-游戏完全解耦重构设计.md)/实施 [13](./13-游戏完全解耦实施计划.md)

**接入一个游戏 = 打一个游戏包（zip）**：game.yaml 声明 + __init__.py 暴露 get_adapter() + 可选只读资源。
平台在**沙箱子进程**中运行它，发布后获得官方 OpenEnv 环境入口 `/api/openenv/{game}`、
/api/{game}/ai/action、/api/{game}/scores 榜单、大厅卡片、会话制游玩（PvE/PvP）、
房间/匹配/观战/回放、模型托管（声明 contract 时）。**官方种子包与用户上传走同一条管线**。
环境交互以 [OpenEnv 契约](../api/openenv.md) 为准：WS 一连接一实例，
`GenericEnvClient.reset/step/state`；旧环境路径已删除，无兼容。包内仍实现现有
`EnvAdapter`，无需在沙箱内安装 OpenEnv；这不是任意复杂外部游戏引擎的现成接入层。

## 1. 游戏包结构

    my-game/
      game.yaml     # 声明（见下）
      __init__.py   # def get_adapter() -> 实现契约的类实例
      weights.npz   # （可选）只读资源：.npz/.npy/.bin（计入 20MB/200 文件）

## 2. game.yaml 声明（规范 v2，完整校验见 backend/ugc_pack.py）

    slug: my-game            # 全局唯一，小写字母/数字/连字符（2-40），创建后不可改
    title: 我的游戏
    description: 一句话介绍
    version: 1.0.0           # x.y.z，更新需递增

    board:                   # 通用渲染（必须）：state.board 的 cell-id 网格
      schema: 2              # 可选（缺省 2）：渲染 v2（见 docs/design/16，完整规范）
      width: 8
      height: 8
      cell: { size: 32, gap: 1, radius: 4, shape: square }      # 可选：格子几何
      background: { kind: checker, colors: ["#f8fafc", "#f1f5f9"] }  # 可选
      palette: { empty: { glyph: "·", color: "#e4e4e7" }, wall: { glyph: "🧱" } }
      hud:                   # 可选：stat/bar/badge/text/miniboard（读 state 路径）
        - { kind: stat, label: 分数, path: score }
      events:                # 可选：state.events 事件名 → 动效/音效
        - { name: eat, effect: { kind: flash, color: "#22c55e", ms: 260 } }
    units: { player: { glyph: "🙂" } }   # 可选：state.units 的单位类型

    assets:                  # 可选：PNG/WebP 精灵（≤256KB/个、≤512px、≤32 个）
      head: { file: "assets/head.png", w: 24, h: 24 }
    sounds:                  # 可选：OGG/MP3/WAV 音效（≤512KB/个、≤16 个）
      eat: { file: "assets/eat.ogg", ms: 400, volume: 0.6 }
    renderer:                # 可选：沙箱自定义渲染器（L3，默认关闭，需管理员开启）
      entry: renderer.js     # 定义 globalThis.Renderer = { init(api), frame(state,t,dt) }

    contract:                # 可选：ONNX 模型托管契约
      in_shape: [1, 64]
      out_shape: [1, 4]
      protocol: simple       # simple（obs→argmax）| composite（model_inputs/model_decode）
      obs_mode: default      # simple 协议用哪个 obs 模式（缺省=info().obs_modes[0]）

    ai_strategies: [greedy]  # 可选：声明后挂 /api/{game}/ai/action（实现 ai_action 或 opponent_action）

    opponents: [greedy, random]   # 可选：PvE 服务端对手策略（opponent_action 实现）
    default_opponent: greedy      # PvE 缺省对手

    pvp:                     # 可选：声明后开放房间/快速匹配/ELO
      enabled: true
      action: choice         # unit（复合指令）| choice（选项索引）
      choices: ["石头", "剪刀", "布"]
      options: { opponent: external }   # PvP 开局附加参数（如 microrts）

    controls:                # 可选：前端键盘映射（数据驱动）
      mode: absolute         # absolute（键→动作值）| relative-turn（键→相对转向）
      direction_field: direction   # relative-turn 时读 state 的朝向字段
      keys: { ArrowUp: [0, "上"], ArrowDown: [1, "下"], ArrowLeft: [2, "左"], ArrowRight: [3, "右"] }

## 3. __init__.py 契约（duck-typed EnvAdapter，沙箱内运行）

    class MyGame:
        score_bounds = (0, 100)                 # 榜单分数范围（属性亦可）

        def info(self) -> dict:                 # 元数据 + state/action/observation JSON Schema
        def new_state(self, seed, options=None) -> dict:
        def step_state(self, state, action, rewards=None) -> dict:
        def validate_state(self, state):        # 非法 raise ValueError
        def validate_action(self, action, state=None):  # 非法 raise ValueError
        def obs(self, state, mode=None):        # 可选（simple 模型协议必需）
        def sample_action(self, state):         # 强烈建议：冒烟/测试用合法动作
        def ai_action(self, payload):           # 可选：/ai/action（payload={state,strategy?,owner?}）
        def opponent_action(self, state, config):  # 可选：PvE 对手（config={"type":"ai","strategy":…}）
        # composite 模型协议（声明 protocol: composite 时必需）：
        def model_inputs(self, state, owner=0): # 逐单位/逐查询的模型输入列表
        def model_decode(self, outputs, state, owner=0):  # masked-argmax 组装动作

    def get_adapter():
        return MyGame()

- `info()` 应返回 `schemas: {state, action, observations}`。三个值都是 JSON Schema
  Draft 2020-12 片段，`observations` 按 `obs_mode` 索引。完整示例见
  `packaged-games/{snake,tetris,microrts}/schemas.py`；旧包缺省时平台只提供宽松回退。
- state 必须是纯 JSON；**同游戏版本、seed、options 必须同轨迹**（回放依赖）；渲染约定：
  state 顶层含 board（cell-id 网格，palette 键必须覆盖；引擎字段非 cell-id 时另存
  render_board）与可选 units: [{id,x,y,type,…}]；渲染 v2 可再带
  events: ["eat", …]（本帧事件，前端据此触发 `board.events` 声明的动效/音效）与
  HUD 读取的派生字段（如 `next_board`、单位 `hp_max`）。
- 渲染条目支持 glyph / sprite / vector 三选一，另有 color/bg/glyph_color/scale/
  opacity/shadow/orient（朝向）/anim（常驻动效）/enter（入场动效）/z，单位还可声明
  owner_colors + owner_field、hp{field,max_field,color}、label{field}；
  完整字段与范围见 [16 渲染能力开放设计](./16-前端渲染能力开放设计.md) §3。
- 沙箱环境：仅标准库白名单 + numpy；**禁网络/禁写文件/禁子进程**；
  包内相对路径读资源（worker 以 cwd=game_dir 启动）；单线程 BLAS。

## 4. 本地自测与发布

    python gdk-ug/test_runner.py my-game        # 元数据/契约/幂等/渲染/20 步推进/PvP/AI 全查

- **官方种子包**：放入 packaged-games/，部署时启动自动播种为 published（作者显示「官方」）；
- **用户上传**：POST /api/v1/ugc/games（multipart file）→ 草稿 → 提交审核 → 通过即公开
  （校验→AST 扫描→沙箱冒烟→发布，与官方包同一条管线）。

## 5. 模型契约（可选）

游戏包声明 contract 后即可上传 ONNX 模型（shape 匹配校验）、PvE 模型对手、模型 vs 模型/内置 AI。
平台只认识两种协议（backend/inference.py）：
- **simple**：obs(state, obs_mode) → 模型 → argmax；
- **composite**：model_inputs(state, owner) 逐组输入 → 批量 run → model_decode（microrts 范例）。

## 6. 测试清单（新游戏必须全绿）

- [ ] gdk-ug/test_runner.py 全绿（元数据/契约/幂等/渲染/PvP/AI）
- [ ] 上传（用户路径或 seed_game）→ 沙箱冒烟通过
- [ ] OpenEnv：`state().environment.schemas` 完整；同一 WS 连接按 version/seed/options
  reset 后逐条 `step({"value": action})`，固定输入的轨迹一致；非法动作/初始化配置明确报错
- [ ] 历史回放使用原 version/seed/options；渲染使用会话 environment.schemas/meta，
  不读取当前 `/schema` 代替历史配置；正常/错误/取消均关闭连接
- [ ] 多实例各用独立连接并遵守每游戏共享 64 个环境上限；SDK Gym 向量包装不是单 HTTP 批量推进
- [ ] 榜单：POST /api/{game}/scores 提交与越界校验
- [ ] PvE 会话：POST /api/v1/{game}/play/sessions {kind:"pve"} → 循环 → done
- [ ] 模型（若声明 contract）：合法/非法 ONNX 各一，评估跑通

## 7. 部署

rsync + 服务器 docker compose up -d --build（前端在 Docker 内构建；官方包随镜像 COPY）；
在 static-docs/api.html 的游戏清单补一行；本指南保持最新。
