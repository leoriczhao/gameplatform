# 18 · 本地训练设计

> 状态：已实现（2026-10-27，分支 `feat/local-training`），待评审合并。
> 关联：设计 17 §0.1（本期范围调整时，这一项被列为优先于舞台重构）、D2（训练面）、D3（同一引擎）、D18（沙箱）、D25（包依赖白名单）。
> 发布方式：破坏性更新（沿用 D36 的偏好）。SDK 升到 0.3.0，gym 包装器改名，默认后端改为 local。

## 1. 问题

产品定位（`docs/pm/01`）中的主用户是模型作者（P3），他们的主旅程第一步就是训练。但到目前为止，训练**只能远程进行**：

- `RemoteVecEnv` 每走一步，n 个槽要按顺序各走一次 OpenEnv WebSocket 往返；
- 每个游戏全平台最多 64 个并发环境，所有用户共享；
- 吞吐取决于往返延迟，增大 n 也摊薄不了网络开销（`sdk/README.md` 已写明）。

规则内核本身是纯 Python 函数（每步微秒到毫秒级），瓶颈完全在网络上。理性的作者会把环境代码拷到本地去训练，但那样得到的环境和线上不保证一致，D3 的价值也就丢了。

## 2. 方案

**平台负责分发游戏包，SDK 在本地运行同一份包代码，再用一致性检查证明本地和线上逐步相同。**

```
训练者机器                                         平台
┌──────────────────────────────┐   GET manifest   ┌───────────────────────────────┐
│ LocalVecEnv / gym backend=local│ ───────────────▶ │ /api/v1/games/{slug}/package  │
│   fetch_package               │ ◀─ sha256/url ── │  （官方包，或 UGC 声明开放）     │
│   ~/.cache/gameplatform/…     │   GET .zip       │ /…/package/{version}.zip      │
│   LocalGame（import 包）       │ ───────────────▶ │  确定性 zip，ETag=sha256，immutable│
│   每步：函数调用，无网络         │                  └───────────────────────────────┘
│ export_onnx（契约读自包）       │
│ evaluate（服务端评估协议，固定种子）│
│ parity_check（本地 vs OpenEnv 逐步比对）│ ── WS ──▶ /api/openenv/{slug}/ws（不变）
└──────────────────────────────┘
```

### 2.1 服务端：包分发

| 端点 | 说明 |
|---|---|
| `GET /api/v1/games/{slug}/package?version=` | 清单：`slug / version / official / sha256 / size / url / meta`（规范化后的 game.yaml）。缺省版本为当前发布版本，也可以指定 active 或 superseded 的历史版本 |
| `GET /api/v1/games/{slug}/package/{version}.zip` | 包本体。由已解包的版本目录**确定性**打包：文件排序、固定时间戳与权限、剔除 `__pycache__`/`.pyc`。同一版本的字节永远相同，所以 `ETag` = sha256，`Cache-Control: immutable` |

**分发策略**：

- 官方包（作者为 system/admin，与目录里显示"官方"的规则一致）始终可以下载；
- UGC 包必须由作者在 game.yaml 显式声明 `local_training: true`，否则返回 403；
- 未发布、已下架、草稿或审核中的版本一律返回 404。

理由：声明开放就等于公开源码，这是作者自己的知识产权决定，平台不能替作者做主。

### 2.2 SDK：本地运行时

| 组件 | 职责 |
|---|---|
| `fetch_package` | 下载清单 → 下载 zip → 校验 size 与 sha256 → 安全解包（拒绝绝对路径和 `..`）→ 先写临时目录再原子改名。缓存键为 `slug/version-sha12`；传入明确的 version 且已缓存时，完全不访问网络 |
| `LocalGame` | 用平台 worker 相同的方式加载包（`spec_from_file_location` + `submodule_search_locations`，把包目录放进 `sys.path`）。调用语义也与 worker 一致：rewards 参数的 TypeError 回退、所有输出经过同样的 JSON 边界（tuple 变成 list），`info()` 同样补上 `grid` |
| `LocalVecEnv` | 与 `RemoteVecEnv` **接口和语义相同**：构造参数、种子分配和每局 +100003、`checked_rewards` 校验、reset 前不可 step、SAME_STEP autoreset、`terminal_obs`、info 字段、NaN 奖励的处理 |
| gym `PlatformEnv` / `PlatformVecEnv` | 由原 `PlatformRemote*` 改名而来，新增 `backend="local"|"remote"`，默认 local |
| `export_onnx` | 模型契约从包的 game.yaml 读取，**删除了 SDK 中硬编码的三个游戏契约**（原来违背 D26，也不支持 UGC）。读取契约只下载、不执行包代码 |
| `evaluate` | 移植服务端 `models.evaluate` 和 `inference.model_action` 的协议（simple 与 composite 都支持），种子固定为 `seed..seed+episodes-1`，两个模型用同一组参数评估时面对的是同一组对局 |
| `parity_check` | 用同一组动作在本地和 OpenEnv 上各跑一局，逐步比对完整 state，返回第一个不一致的步数 |

### 2.3 信任边界

- 在服务器上，UGC 代码跑在沙箱里（D18）。在训练者的机器上，代码直接在本进程运行，**没有沙箱**。
- 官方包直接运行。UGC 包必须显式传入 `trust_remote_code=True`，这与 Hugging Face 的惯例一致。错误提示会说明这是第三方代码。
- 公开的 UGC 版本经过平台的静态扫描（D25 白名单）和人工审核，这能降低风险，但不能替代沙箱。文档如实写明这一点。

## 3. 一致性如何保证

只依赖一个机制：**同一份字节 + 同一套调用语义 + 测试证明**。

- **同一份字节**：manifest 中的 sha256 绑定版本，SDK 下载后校验。
- **同一套调用语义**：`LocalGame` 和 `LocalVecEnv` 逐条复刻 worker 的 `_dispatch`，以及 OpenEnv `PlatformEnvironment` 的 reset/step。
- **测试证明**（`tests/test_local_training.py`）：
  - snake / tetris / microrts（默认对手，以及 light_rush 对手）在同种子、同动作下逐步比对完整 state；
  - snake 的 grid / rotwin / features / state 四种观测、自定义奖励、autoreset 的终局观测，本地与远程逐个数组相等；
  - 一个开放本地训练的 UGC 包（其中返回 tuple，用来验证 JSON 边界）也做一致性比对；
  - 反向测试：故意让本地在第 5 步偏离，`parity_check` 必须报出 `mismatch_at == 5`。

剩余风险：训练者本机的 numpy 版本与平台 venv 不同，可能让浮点观测出现极小差异。规则逻辑本身是纯 Python，不受影响。`parity_check` 是给用户的自检手段。

## 4. 实测吞吐

测试条件：本机回环地址（`live_server`），n=16，每项持续 4 秒，随机动作，单进程。microrts 每步下发空指令，`obs_mode=state`。

| 游戏（观测） | LocalVecEnv | RemoteVecEnv（回环） | 倍数 |
|---|---|---|---|
| snake（rotwin，1334 维） | 5,855 步/秒 | 483 步/秒 | 12× |
| tetris（grid） | 8,284 步/秒 | 573 步/秒 | 14× |
| microrts（state） | 2,579 步/秒 | 739 步/秒 | 3.5× |

**回环地址是远程训练的最好情况。** 远程模式下，n 个槽依次往返，所以总吞吐上限约为 `1 / 往返延迟`，与 n 无关：往返 30ms 时约 33 步/秒，80ms 时约 12 步/秒，而且还要和其他用户共享 64 个并发名额。按 30ms 估算，本地 snake 比线上远程快约 **170 倍**。

本地吞吐只受本机 CPU 限制，也可以横向扩展：用 Gymnasium 的 `AsyncVectorEnv` 包一层 `PlatformEnv`，就能多进程并行。

实现过程中做过两处优化：每步只计算一次观测；对纯数值列表形式的观测跳过 JSON 往返，因为两者结果完全相同（逻辑见 `LocalGame.obs_array`）。state 仍然完整经过 JSON 边界，以保证一致性。

## 5. 不做 / 后续

- **不做**：在本地复刻沙箱（Landlock/seccomp 只在 Linux 上可用，而且会拖慢训练）；把包发布到 PyPI（平台本身就是包注册中心，并且按版本精确绑定）。
- **后续**：
  - 服务端模型评估仍使用随机种子、3 局，结果不可复现，也不可横向比较。建议改成和 SDK `evaluate` 相同的固定种子集，让"本地评估"和"上线评估"的分数可以直接对照。
  - `sdk/gameplatform/microrts_obs.py` 是手工维护的特征副本。现在可以直接调用 `LocalGame.model_inputs` 拿到权威特征，副本可以删除。
