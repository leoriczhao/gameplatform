## 1. 目标

- 多用户：每个用户有自己的资料、模型、战绩、积分
- 低摩擦：游客可体验 PvE；注册只需用户名+密码
- 可治理：配额、限流、封禁、管理角色

## 2. 账号模型

```
users
  id            INTEGER PK
  username      TEXT UNIQUE（3-24，字母数字下划线）
  password_hash TEXT（bcrypt）
  nickname      TEXT（显示名，可空=username）
  role          TEXT（user | admin，默认 user）
  created_at    REAL
  status        TEXT（active | banned）
```

- **注册** `POST /auth/register {username, password}`：校验唯一性 → bcrypt 哈希 → 自动登录返回 JWT
- **登录** `POST /auth/login`：失败统一返回 401（不泄露"用户不存在"）
- **JWT**：HS256，`sub=user_id`，有效期 7 天；secret 走环境变量 `PLATFORM_SECRET`（部署时生成）
- **游客** `POST /auth/guest`：签发 `role=guest` 的短期令牌（12h）或纯 IP 标识（见下）

## 3. 游客模式

| 能力 | 游客 | 注册用户 |
|---|---|---|
| 浏览大厅/排行榜/文档 | ✅ | ✅ |
| PvE 游玩（会话 API） | ✅（同时最多 1 个会话） | ✅（最多 8 个） |
| PvP 人 vs 人 | ❌ | ✅ |
| 上传模型 | ❌ | ✅ |
| 模型参战 / 创建对战 | ❌ | ✅ |
| 提交 PvE 成绩 | ✅（标记游客昵称，不参与积分） | ✅ |
| 环境 API | ✅ IP 限流 | ✅ 用户限流（更宽） |

## 4. 限流与配额

统一令牌桶，按身份分档：

| 维度 | 游客（按 IP） | 注册用户（按 user_id） |
|---|---|---|
| env/new_batch + env/step | 60 req/s | 120 req/s |
| play/actions | 10 req/s | 30 req/s |
| ai/action | 30 req/s | 60 req/s |
| scores 提交 | 1 req/s | 5 req/s |
| 模型上传 | — | 20 MB/模型，每游戏最多 5 个活跃模型 |
| 并发会话 | 1 | 8 |
| 并发对战（模型） | — | 4 场 |

超限返回 `429 {"detail":"rate limited","code":"RATE_LIMITED"}`，响应头带 `Retry-After`。

## 5. 鉴权实现要点

- FastAPI dependency：`get_current_user(request) -> User | Guest`
- 游客与用户共用一个 `Principal` 模型（`id/username/role`），业务按 role 分支
- 敏感操作（删除模型、改资料）校验 `principal.id == resource.owner_id`
- 管理接口校验 `role == admin`
- 密码策略：≥8 位；bcrypt cost=12
- 防滥用：注册接口限流（每 IP 5 次/小时）

## 6. 前端账号体验（React）

- 顶栏登录态：未登录显示「登录 / 注册」按钮；已登录显示昵称 + 头像 + 下拉（我的模型 / 战绩 / 退出）
- 登录/注册用全局弹窗（`components/LoginProvider.jsx`，`useLogin()` 唤起）；JWT 存 localStorage（`gp_token`）
- 401 全局拦截：清除 token → 弹登录框
- 游客：进入游戏时自动静默获取 guest 令牌（如未注册）

## 7. 迁移与兼容

- 现有 `scores` 表加 `user_id`（可空 = 历史匿名成绩）+ `guest_name` 迁移
- 现有排行榜行为不变：历史成绩继续显示
- 后续 PvP 积分单独 `ratings` 表，不混入 PvE scores
