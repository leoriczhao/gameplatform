# 12 · 游戏完全解耦重构设计（Stream）

> **历史设计，不作为当前环境 API 手册。** 本文保留当时的决策、接口示例与验收记录；
> 环境交互相关内容已被 [OpenEnv 契约](../api/openenv.md) 取代。旧环境 API 已删除，
> 不保留兼容；当前架构见 [架构总览](../architecture.html)，平台业务与回放见
> [运行时契约](../api/runtime-contracts.md)。下文不代表本次切换已部署或通过测试。

> 状态：已交付（历史设计，2026-08）
> 读者：实施 agent / 新会话
> 配套实施计划：[13-游戏完全解耦实施计划](./13-游戏完全解耦实施计划.md)

## 0. 一句话

**取消「内置游戏 / UGC 游戏」的区分：平台只认识一种东西——「游戏包」。**
自带游戏（snake/tetris/microrts）也打包成与用户上传完全同构的游戏包，走同一条
「校验 → 静态扫描 → 解包 → 沙箱冒烟 → 注册（ProxyAdapter）」管线，在首次启动时
作为**官方种子游戏**自动入库发布。平台核心（backend/ 与 web/）**不再包含任何具体
游戏的代码或硬编码分支**，允许破坏性改动。

## 1. 背景与现状（2026-08 核对）

现状存在两套游戏接入机制，平台核心对具体游戏有多处硬编码：

| 面 | 现状 | 问题 |
|---|---|---|
| 内置游戏 | backend/games/{snake,tetris,microrts}/ Python 包，import 时自注册进 registry，与平台**同进程**运行 | 游戏代码长在平台仓库里 |
| UGC 游戏 | zip 包 + 沙箱子进程 + ProxyAdapter 走 IPC | 与内置是两套机制 |
| inference.py | snake/tetris/microrts 的 obs→输入、输出→动作映射、契约表**全部写死**（31 处游戏名） | 模型面最深耦合 |
| models.py | evaluate 按游戏分叉 | 每个新游戏都要改平台代码 |
| matches.py | 模型 vs 模型 if game != "microrts" 白名单 + {"opponent":"external"} 硬编码 | 同上 |
| sessions.py | PvE 默认对手 if adapter.game_id == "microrts" | 同上 |
| main.py | 每个内置游戏的 SPA 路由、每游戏 router 挂载 | 同上 |
| 前端 | Snake/Tetris/Microrts/MicrortsPvp 四个专属页面 + microrts 专用 BoardCanvas | 新游戏要写新页面 |

UGC 那条路（ProxyAdapter + registry + 动态路由 + 动态契约）已经是**正确的目标形态**。
本设计把内置游戏也拉上这条路，并把平台里所有残留的游戏名硬编码清掉。

## 2. 目标架构

    ┌────────── Stream 平台运行时（游戏无关，零游戏名硬编码）──────────┐
    │ backend/                                                       │
    │  registry          注册中心（GAMES dict + 挂载回调）           │
    │  ugc_runner/worker 沙箱执行（资源限制 + 禁能桩 + JSON IPC）    │
    │  ugc_pack/static   包校验 / AST 扫描（通用）                   │
    │  ugc.py            入库/版本/状态机/种子发布（通用）           │
    │  env_routes        按注册表动态挂 /api/{slug}/env/* 等         │
    │  play/sessions     PvE/PvP 会话（纯接口调用 + 能力声明）       │
    │  models/matches    模型托管/评估/对战（通用模型协议 §4.4）     │
    │  inference         ONNX 运行器 + 通用协议调度（不认得游戏）    │
    │  seed_loader       启动把 packaged-games/* 播种并发布         │
    ├───────────────────────────────────────────────────────────────┤
    │  web/：UgBoard/UgPlay/UgPvp 通用渲染，全部 game.yaml 数据驱动 │
    │  路由统一：/games/{slug}（单机）、/games/{slug}/pvp（对战）   │
    └───────────────────────────────────────────────────────────────┘
                  ▲ 全部走同一条管线（与用户上传完全一致）
                  │
    packaged-games/{snake,tetris,microrts}/  官方种子游戏包（与 UGC 同构）
    game.yaml + __init__.py(get_adapter) + 资源文件（如 weights.npz）
    用户上传的游戏包（gdk-ug 模板，规范 v2）

不变量：**平台能力 = 包声明什么就给什么**（pvp 声明→PvP；contract 声明→模型托管；
ai_strategies 声明→/ai/action；opponents 声明→PvE 对手）。任何游戏（官方或用户）
都不再需要改平台代码。

## 3. 游戏包规范 v2（在 [10](./10-用户上传游戏设计.md) §4 基础上扩展）

### 3.1 新增/修改的 game.yaml 字段

```yaml
slug: snake              # 全局唯一；官方种子包先占
title: 贪吃蛇
description: ...
version: 1.0.0
board: { width: 20, height: 20, palette: {...} }
units: {...}             # 可选

# —— 以下为 v2 扩展 ——
contract:                # 模型托管契约（v2 增 protocol/obs_mode）
  in_shape: [1, 1334]
  out_shape: [1, 3]
  protocol: simple       # simple | composite
  obs_mode: rotwin       # simple 协议用哪个 obs 模式（缺省 = info().obs_modes[0]）
  # simple：动作 = obs(state, obs_mode) → 模型 → argmax（obs 重塑为 in_shape）
  # composite：model_inputs(state) 多组输入 → 模型逐组 → model_decode(outputs, state)

ai_strategies: ["binary"]          # 声明后挂 /ai/action（不变）

pvp:
  enabled: true
  action: choice         # unit | choice（不变）
  choices: ["石头","剪刀","布"]
  options: {...}         # v2 新增：PvP 开局附加参数（原 microrts 的 {"opponent":"external"}）

opponents: ["worker_rush","light_rush","ranged_rush"]   # v2 新增：PvE 服务端对手策略
default_opponent: "worker_rush"                         # v2 新增：PvE 缺省对手

controls:                # v2 新增：前端键盘映射（数据驱动）
  mode: relative-turn    # absolute（键→动作值）| relative-turn（键→相对转向）
  direction_field: direction     # relative-turn 时读 state 的朝向字段
  keys: { ArrowUp: [3, "上"], ArrowDown: [1, "下"], ArrowLeft: [2, "左"], ArrowRight: [0, "右"] }
```

- **资源文件**：扩展名白名单增加 .npz/.npy/.bin（只读资源，计入 20MB 总限与 200 文件
  上限；冒烟时校验 np.load 可用）。禁止任何可执行/可写语义。
- **os 从白名单移除**：worker 以 cwd=game_dir 启动，包内一律相对路径读资源
  （np.load("weights.npz")）。当前 snake 包内 os 用法在打包时改掉。
- EnvAdapter 契约扩展两个**可选**方法（沙箱内实现）：
  - model_inputs(state) -> list（composite 协议必需；simple 协议省略）
  - model_decode(outputs, state) -> action（composite 协议必需；simple 协议省略）

### 3.2 与规范 v1 的兼容

- v1 字段（slug/title/version/board/units/contract/pvp/ai_strategies）全部保留；
  已有 UGC 游戏包（guess-number/rock-paper-scissors/sokoban 等）无需改动。
- contract.protocol 缺省 = simple（等价于现行为）。
- opponents/controls 缺省 = 无（行为与现在一致）。

## 4. 平台运行时改造（backend/）

### 4.1 删除

- backend/games/ 整个目录（游戏代码迁入 packaged-games/ 各自包内）。
- inference.py 的 snake_obs/tetris_grid/microrts_commands/_mask_for/_unit_input/
  _mr_grid 等游戏专属函数（迁入对应游戏包的 model_inputs/model_decode）。
- registry「来源」概念对外暴露：/api/games 删除 source 字段；官方种子游戏与用户
  游戏完全同构展示，作者字段显示「官方」。
- main.py 里内置游戏的 SPA 路由与游戏名挂载循环。

### 4.2 种子游戏加载器（seed_loader，新增）

启动顺序改为：

1. ensure_schema()（含 auth/social 表）。
2. **播种**：遍历 packaged-games/*，对每个包执行与用户上传完全相同的管线
   （ugc_pack.validate_package → ugc_static.scan_dir → 解包 → 沙箱冒烟），
   以**系统作者**（admin 账号，不存在则跳过播种并告警）写入 ugc 表：
   - 新 slug → 建游戏 + 版本，状态直接 published（官方包免人工审核）；
   - 已有 slug 且版本号更高 → 新版本直接 active（官方包免审）；
   - 版本号相同 → 跳过（幂等）。
3. load_published_into_registry()：所有 published（官方 + 用户）统一注册为
   ProxyAdapter 并挂路由——与现逻辑一致，无需区分。

### 4.3 各模块去游戏化

| 模块 | 改动 |
|---|---|
| sessions.py | 删除 adapter.game_id == "microrts" 分支：PvE 对手与默认对手改由包声明驱动（opponents/default_opponent，经 adapter.info()/meta 读取）；_opponent_commands 已是通用调用（opponent_action），保留；PvP new_state 用 adapter.pvp_options（已能力化） |
| matches.py | 模型 vs 模型删除 microrts 白名单，改为「该游戏声明了 contract 即支持」；_run_model_match 用通用模型协议（§4.4）；对手侧 = 对方模型（通用协议）或 opponent_action 声明策略 |
| models.py | evaluate 只保留一条通用路径（现 P5 的 else 分支升级为唯一实现）：new_state → 循环 {generic_model_action → step_state}；计分取 state.score/reward 通用字段 |
| inference.py | 瘦身为：load_model/check_contract（契约来自 adapter 的 meta.contract）/generic_model_action；删除全部游戏专属函数 |
| platform_api.py | 目录删除 source；种子游戏 author="官方"（由 ugc 表 owner 决定） |
| env_routes.py | 已通用；仅清理文档串里的游戏名示例 |
| matches_routes.py | CreateMatch.game 改为必填（删默认 microrts） |
| registry.py | 保留 register/unregister/sorted_games；_SOURCES 对外不再暴露 |
| ugc.py | _ingest 删除内置游戏名集合（种子包先占 slug，天然防冲突）；新增 seed_game()（系统作者免审发布）；其余不变 |
| main.py | 删 import games 与内置挂载；加种子加载器调用；SPA 路由统一 /games/{slug}、/games/{slug}/pvp |

### 4.4 通用模型协议（模型面解耦的关键）

平台侧 generic_model_action(game, sess, state) 只有两种协议，不认得任何游戏：

- **simple**：x = adapter.obs(state, obs_mode) → sess.run(x) → argmax（现 UGC 行为）。
- **composite**：inputs = worker.model_inputs(state)（沙箱内逐单位/逐查询构造输入）
  → 平台批量跑 ONNX → action = worker.model_decode(outputs, state)（沙箱内做
  masked-argmax + 命令组装）。

microrts 的模型协议（grid+unit feats、140 logits mask、命令构建）从 inference.py
**原样迁入 microrts 游戏包**，实现 model_inputs/model_decode；snake/tetris 用 simple
协议（obs 已实现）。

平台只新增两个 worker op：model_inputs、model_decode（与现有 obs 同模式）。

### 4.5 沙箱顺带加固（记录为明确取舍）

- worker 以 cwd=game_dir 启动，删除包内 os 依赖；支持多文件包与相对导入
  （sys.path 插入游戏目录 + 按包加载 + sys.modules 注册）。
- **rlimit 实测校准（G2 交付时修正）**：
  - AS 512MB → **768MB**（numpy 2.x import 在 512MB 下挂起，768MB 可导入；
    >768MB 的恶意分配仍失败）；
  - NPROC 64 → **128**（OpenBLAS import 默认起 16 线程会撞 NPROC；
    并在 worker 内强制 OPENBLAS_NUM_THREADS=1 / OMP_NUM_THREADS=1，
    消除高并发下的线程竞争，同时保证同 seed 确定性）。
- 已知缺口：numpy 自带的文件加载（np.load）不经过 builtins.open 拦截，可读到游戏
  目录外的文件。本次重构**接受该风险**（与 D18 一致：进程级隔离 + rlimit + 无网络，
  破坏面有限），并记录：v2 演进为 gVisor/Firecracker/只读根文件系统（worker 以只读
  bind 挂载 venv + 游戏目录启动）。

## 5. 前端改造（web/）

**原则：删除全部游戏专属页面与组件，只剩数据驱动的通用页面。**

| 改动 | 说明 |
|---|---|
| 删除 | pages/Snake.jsx、pages/Tetris.jsx、pages/Microrts.jsx、pages/MicrortsPvp.jsx、components/BoardCanvas.jsx |
| 路由 | 统一 /games/{slug} → UgPlay、/games/{slug}/pvp → UgPvp（/games/ugc/{slug} 保留为别名或直接移除） |
| UgPlay 增强 | ① 键盘映射：controls.mode=absolute（键→动作值）；controls.mode=relative-turn（通用「相对转向」逻辑：读 state[direction_field] 把 上/下/左/右 映射为 0=左转/1=直行/2=右转，逻辑平台内置、字段名由数据指定）② HUD 展示 tick/得分/奖励 通用字段 |
| UgPvp 增强 | unit 型从「JSON 输入」升级为数据驱动的指令构建器：选单位 → 按 info().actions 选指令 → 按 info().directions 选方向 →（可选）类型；choice 型不变 |
| Watch/Arena/WatchReplay | 审计并通用化 microrts 专属展示（bank/damage 等）：HUD 字段改为按游戏 info() 声明渲染，无声明则只显示棋盘 + 双方提交状态 |
| 大厅 | 无内置/UGC 区分；官方游戏作者显示「官方」 |

**取舍（明示）**：snake/tetris 从专属 canvas + 键盘手感到通用棋盘渲染 + 数据驱动
键盘映射，交互精细度会下降（例如贪吃蛇的「眼睛」、方块的旋转预览）。这是解耦的
代价；通用渲染器已支持 emoji/颜色/单位，视觉可接受，后续可在通用渲染器上按数据
增强，而不是给游戏写专属代码。

## 6. 官方种子游戏包（packaged-games/）

三个内置游戏改写为规范 v2 游戏包，与用户上传包完全同构：

| 包 | 改写要点 |
|---|---|
| snake/ | env.py+ai.py 迁入；删除 import os（相对路径读 weights.npz）；weights.npz 打包进包（672KB）；game.yaml 声明 palette/units（蛇身逐节色阶）+ contract(simple, 1334→3) + controls(relative-turn, direction_field=direction) + ai_strategies；模型契约与动作空间**保持不变**（0=左转/1=直行/2=右转），旧模型不失效 |
| tetris/ | env.py+baseline.py 迁入（纯函数，几乎原样）；game.yaml 声明 palette/units + contract(simple, (1,2,20,10)→(1,4)) + controls(absolute) + ai_strategies |
| microrts/ | env.py+strategies.py 迁入；模型协议（grid/unit 特征、mask、命令构建）迁入包内 model_inputs/model_decode；game.yaml 声明 palette/units + contract(composite, 1546→140) + pvp(unit, options:{opponent:external}) + opponents + default_opponent |

三个包的 __init__.py 均只暴露 get_adapter()（与 UGC 模板一致），适配器层
（原 adapter.py 的 pydantic 请求模型等）不再存在——平台侧统一用
ProxyAdapter/UGCAIRequest。

## 7. 破坏性变更清单（明确）

1. backend/games/ 目录删除（游戏代码全部迁出平台仓库）。
2. /api/games 删除 source 字段（客户端如有依赖需同步）。
3. POST /api/v1/matches 的 game 字段改为必填。
4. 前端删除四个专属游戏页面与专属路由，统一走 /games/{slug}。
5. 内置游戏的运行时从「进程内」变为「沙箱子进程」（IPC 开销见 §8 压测结论，可接受）。
6. 模型契约命名统一为包声明（snake/tetris/microrts 契约 shape 不变，旧模型继续可用）。
7. SPA 路由 /games/microrts 等迁移到 /games/snake 等新通用路由（旧链接失效，可接受）。

**不变**：游戏 slug 不变（snake/tetris/microrts），榜单/积分/对局/回放历史数据全部
保留；用户已上传的 UGC 游戏包不需任何改动；所有 HTTP 路径（env/play/scores/ai）不变。

## 8. 风险与权衡

| 风险 | 评估与对策 |
|---|---|
| 沙箱 IPC 性能 | 已有实测（P5 压测）：5 个 UGC 游戏并发 env p99 ≈ 内置游戏 p99（1410-1479ms vs 1644ms），开销可接受 |
| 前端体验降级 | 通用渲染 + 数据驱动键盘尽量保留手感；见 §5 取舍 |
| numpy 绕过 open 拦截 | 接受（D18 进程级隔离），v2 上只读根文件系统 |
| 启动播种时长 | 3 个包冒烟各 ~20 步 + 解包，秒级；启动顺序按 §4.2 |
| 测试全量改写 | 内置游戏测试改走「种子包 → ProxyAdapter」或 GDK 测试器；见 13 |

- 全量 pytest 绿 + 前端 build 通过 + 生产验收。
