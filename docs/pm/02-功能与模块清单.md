# 02 · 功能与模块清单

> 关联：[01-定位与用户](./01-定位与用户.md) · [03-信息架构草案](./03-信息架构草案.md) · [04-组件与页面地图](./04-组件与页面地图.md)  
> 用途：Game UI / Frontend / Backend 各自对照范围；**状态以共享盘代码为准**（调研日 2026-10-14）。

图例：

- **与大定位关系**：`主` = 训练闭环直接相关；`次` = 验证/社交/运营等支撑；`规划` = 蓝图有、代码未齐  
- **状态**：`已上线` = 代码路径齐全且设计标注已交付；`部分` = 有基础能力缺蓝图进阶；`规划` = 设计有、实现未见或仅占位

## 文档与代码不一致 / 缺口（调研笔记）

1. **定位 vs 现网文案**：Lobby Hero 主按钮仍以「战绩」为首；顶栏顺序为战绩→模型→上传…，API 文档为外链——与已确认「顶栏优先模型/API、Hero 推训练闭环」不一致（属目标 IA，待 Game UI）。  
2. **蓝图第一天旅程**仍写玩法优先；以 `docs/pm/01` 为准。  
3. **`docs/design/00-README` Decision Log 中 D27 条文**有「对战中心磁贴条」旧述，与设计 14「撤销 /arena」及代码冲突；**以设计 14 + `App.jsx` 为准**。  
4. **根 README** 仍写 pages 含「对战中心」——过时。  
5. **Lobby UGC 作者徽标**：`isUgc = false` 写死，公开 UGC 卡片不显示作者。  
6. **蓝图模块状态表**部分仍标 ⬜，但 v1.0 批次与 UGC/解耦/渲染已交付——以本清单「状态」列为准。  
7. **进阶缺口（真缺）**：模型广场/主页、模型排位池、成就、赛季、锦标赛、大厅聊天/私信、多副本 Redis（D12 v2）。
