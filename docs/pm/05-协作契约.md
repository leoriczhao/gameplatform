# Stream 协作契约（PM 主导）

> **Leader**：Stream PM  
> **原则**：制品交接，不聊天仪式；每阶段一张契约卡 + Done 判据；**默认少人审**——人只拍板定位/破坏性 API 与生产发版。  
> **代码根**：`/workspace/gameplatform` · 线上：`games.cree1p.com`

## 0. 信封（每张契约卡必填）

```yaml
id: CHANGE-YYYYMMDD-短名          # PM 发号
version: 1
owner: stream-pm                  # 契约所有者恒为 PM
status: draft | active | blocked | done | archived
gate: none | human-scope | human-ship
user_ack: null                    # 人闸通过时填写 {by, at, stage}；执行方只认此字段
depends_on: []
artifacts: []
done_when: []
assignee_next: stream-pm | game-ui | stream-dev | stream-qa | kr-ops | none
stage: specify | ui | plan | impl | qa | ship
stage_event: null                 # 如 stage.ready / stage.accepted / qa.ready / ship.done
```

状态机：`draft → active → done → archived`；失败回 `blocked`，由 PM 改版或砍范围。  
**单一真相**：阶段推进以本文件为准；群消息只引用 `id` + 事件名，不口头改状态。

## 1. 角色与所有权

| 角色 | Agent | 可写 | 只读 | 不可做 |
|---|---|---|---|---|
| **Leader** | Stream PM | `docs/pm/`、契约卡、阶段放行（dsh **可用不强制**） | 全仓 | 不改业务代码、不部署 |
| UX/UI | Game UI / UXUI | Penpot、`docs/pm` 下 UI 规格摘录、体验反馈 | `docs/pm`、`web/DESIGN.md` | 不改 `web/` / `backend/` |
| **Dev** | Stream Dev | `web/`、`backend/`、`docs/api/`、OpenAPI（**经 dsh ACP 实现**） | 契约卡、Penpot、`web/DESIGN.md` | 不擅自改 IA/路由硬约束；破坏性 Schema 须 human-scope；**禁止默认绕过 dsh** |
| QA | Stream QA | `report-qa.md`、冒烟/回归结果（**动仓强制 dsh**） | 契约卡、OpenAPI、候选/线上只读 | 不改业务代码、不替 Dev 做开发自测、不部署 |
| Ops | KR 运维 | 部署配置/线上（dsh **可用不强制**） | 发版清单、健康检查项 | 不改产品范围 |

**为何 Dev 合一**：FE/BE 拆开时交接与「等对方」成本高于本仓库规模；同一 bot 端到端改 `web/`+`backend/`，OpenAPI 仍是硬契约（对 QA/文档），但是**内部实现契约**，不再做 bot 间并行排队。  
历史角色 Stream Frontend / Stream Backend：**停用**，不再接新任务；旧变更报告路径可保留只读。

**自测 vs QA**：**开发自测**归 Stream Dev（`report-dev.md`）；**QA** 做独立冒烟、回归、契约/路径抽检。

**dsh 接入（共享 box 可用；规则按「是否动仓」）**：CLI `~/.local/bin/dsh`，profile `~/.dsh/profiles/acp`（DeepSeek account；Node ≥22）。工具链就绪**不算人闸**。

| 场景 | 谁 | 强度 | harness / 注明 |
|---|---|---|---|
| 改 `web/` / `backend/` / `docs/api` | Stream Dev | **硬门槛** | `report-dev.harness: dsh-acp`（可附 session/profile）；不可用则 `blocked` |
| 写仓内 QA 制品（冒烟脚本、夹具、`report-qa` 配套脚本） | Stream QA | **动仓强制** | `report-qa` 建议 `harness: dsh-acp` |
| 写仓内 UI 制品（`docs/pm/changes/.../ui/` handoff/mock） | UXUI | **动仓强制**；Penpot 出稿**不经** dsh | ui-handoff / 回报注明即可，勿与 Dev 的 harness 混名 |
| `specify` / `plan` / 契约文稿 | Stream PM | **可用，不强制** | plan 须写明 Dev（及动仓的 QA/UX）走 dsh |
| 运维脚本 / 巡检整理 | KR 运维 | **可用，不强制**（动仓脚本建议走） | ship 可注明 |

例外仅限用户当轮点名。禁止业务代码默默绕过 dsh。

## 2. 流水线（PM 推进）

```
PM: specify.md
  → PM 放行（仅定位/IA/破坏性范围触及 human-scope 时等人）
Game UI: ui-handoff（无 UI 则跳过）
  → PM 放行（视觉迭代默认 PM 自决，不默认找人）
PM: plan.md（切 Dev / QA / Ops）+ OpenAPI 差分说明
  → PM 放行
Stream Dev: 实现 + report-dev（含开发自测）
  → PM 收齐
Stream QA: report-qa（或 plan「免测」）
  → PM 收敛
Ops: ship.md
  → human-ship（唯一默认必经人闸）
归档
```

### 2.1 `specify.md`（PM 写，半页封顶）

路径：`docs/pm/changes/<id>/specify.md`

```markdown
# <id> specify
- 要解决的问题：（1–3 句）
- 非目标：
- 用户与主旅程触点：（引用 01）
- IA / 路由影响：（无 | 列出；硬约束含「不恢复 /arena」）
- 成功指标：
- 风险 / 开放问题：
```

**Done**：字段齐全。

### 2.2 Game UI 交接包

路径：`docs/pm/changes/<id>/ui/` + Penpot

```markdown
# <id> ui-handoff
- penpot: <url 或 file id>
- 页面/状态清单：（相对 04 的增删改）
- 组件差分：
- 对照 web/DESIGN.md：（一致 | 例外）
- 导出：`ui/export/`
```

**Done**：Penpot 可开；覆盖 specify 触点。  
**人审**：默认不需要；仅当改动触及已拍板 IA/定位时走 human-scope。同一 specify 下 UI `rejected` 建议 ≤2 轮，再多须改 specify 或砍范围。

### 2.3 `plan.md`

路径：`docs/pm/changes/<id>/plan.md`

```markdown
# <id> plan
## 任务
- [ ] Dev: …（可同时含 web / backend）
- [ ] QA: …（或「本变更免测：理由」）
- [ ] Ops: …（可无）

## 接口（硬契约 / 文档）
- openapi_diff: path 或「无 API 变更」
- 兼容性: 兼容 | 破坏（破坏 → gate: human-scope）

## 验证
- 开发自测: Dev report-dev
- QA: smoke / 回归 / 契约抽检
```

**Done**：任务可勾；破坏性已标 gate。

### 2.4 实现回报（Stream Dev）— 含开发自测

路径：`docs/pm/changes/<id>/report-dev.md`

```markdown
# <id> report-dev
- harness: dsh-acp | blocked（理由）| exception（须用户当轮点名）
- commits / 变更摘要:
- 覆盖任务: [x] …
- 触及: web | backend | both
- 开发自测: 通过 | 失败（附日志）
- OpenAPI / docs/api: 无变更 | 已更新（路径）
- 契约偏差: 无 | 说明（须 PM 改版）
```

（过渡期仍可写 `report-fe.md` / `report-be.md`，但新变更统一 `report-dev.md`。）

**Done**：任务勾完或显式砍掉；开发自测通过；`harness` 已填且非默默绕过 dsh。

### 2.5 QA 回报

路径：`docs/pm/changes/<id>/report-qa.md`

```markdown
# <id> report-qa
- 环境: 本地 | 候选 | 生产只读
- 范围: 冒烟 | 回归 | 契约抽检
- 结果: 通过 | 失败（复现）
- 非目标: 不代替 Dev 自测；不改代码
```

**Done**：QA 任务覆盖或 plan 免测；失败有复现。通过后才开 ship。

### 2.6 发版卡（Ops）

路径：`docs/pm/changes/<id>/ship.md`

```markdown
# <id> ship
- 制品版本 / 镜像 / commit:
- 迁移 / 回滚:
- 健康检查:
- gate: human-ship
```

**Done**：回滚可读；`STATUS.user_ack` 已填后才部署。

## 3. 消息池（少说人话）

| 事件 | 谁发 | 载荷 |
|---|---|---|
| `contract.opened` | PM | `id` + specify 路径 |
| `stage.ready` | 执行方 | `id` + stage + 制品路径 |
| `stage.accepted` / `rejected` | PM | `id` + 原因（拒时必填） |
| `blocked` | 任一 | `id` + 缺什么 |
| `qa.ready` | QA | `id` + report-qa |
| `ship.requested` | PM | ship.md；且 STATUS.gate=human-ship 已有 user_ack |
| `ship.done` | Ops | 镜像 / commit 回填说明 |

订阅：只处理与自己相关的事件；**禁止**用长对话替代改契约文件。

## 4. 人闸（尽量少）

默认**只有**生产发版必须人审：

1. **human-ship**（默认必经）：生产 `games.cree1p.com` 发版  
2. **human-scope**（例外才开）：定位/用户主次变更、IA 硬约束（含恢复 `/arena`）、破坏性 API/Schema、明显范围膨胀  

**不算人闸**：UI 亮色/紧凑等视觉迭代、无 API 的实现细节、工具链就绪（如 dsh）、PM 阶段放行。  

**协议**：人确认后由 PM（或当事人 bot）写入 `STATUS.yaml`：

```yaml
gate: human-ship   # 或 human-scope
user_ack:
  by: leoric
  at: "2026-10-15T15:00:00+08:00"
  stage: ship      # 或 specify / ui …
```

执行方（含 Ops）**只认 `user_ack`**，不要求再在另一条私聊「亲口确认」；群内转述无效、文件有效。

## 8. 群与订阅（执行位）

群上限 6 人。推荐常驻：

| 席位 | Agent | 何时说话 |
|---|---|---|
| 1 | Stream PM | 开单、放行、收口 |
| 2 | Stream Dev | plan 后实现 |
| 3 | Stream QA | impl 后测（或 plan 免测则静默） |
| 4 | KR 运维 | ship 阶段 |
| 5 | UXUI | **订阅制**：仅 `assignee_next=game-ui` 或 plan 含 UI 任务时响应；其余变更不 @、不汇报 |
| 6 | 协作架构（可选） | 契约/卡点；日常流水线不插话 |

编排默认走私聊；需要全员对齐时才进群。  
`Stream 协作` 可作备份编排室；与 Gameplatform 职责勿双线同时指挥同一 CHANGE。
