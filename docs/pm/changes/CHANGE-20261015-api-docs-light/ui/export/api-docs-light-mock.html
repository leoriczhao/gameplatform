Stream API 文档

多游戏 RL 平台：每个游戏提供官方 OpenEnv 环境交互（WS 会话，训练算法在客户端、环境在后端）与前端界面（人工 / 内置 AI 演示 / 模型）。注册账号后可用会话制对战（PvE / 人 vs 人 PvP）、ONNX 模型托管与模型对战。Base URL：https://games.cree1p.com，业务 HTTP 与环境 WS 均使用 JSON。本文描述当前契约，不代表本次变更已部署或完成验收。平台业务交互式文档见 Swagger UI 与 OpenAPI schema。

账号与鉴权 v1

密码 bcrypt(cost 12) 存储；登录/注册返回 JWT（HS256）。需要鉴权的接口带请求头 Authorization: Bearer <token>。用户名 3-24 字符，密码 8-128 字符。

{"username":"alice","password":"password123"} → {"token":"eyJ…","user":{…}}

POST /api/v1/auth/guest 游客身份

游戏接入 GDK（v2，13 G3 后统一为游戏包）

接入新游戏 = 打一个游戏包（zip：game.yaml 声明 + __init__.py 暴露 get_adapter() + 可选只读资源）。平台在沙箱中运行它，并自动获得 OpenEnv 环境入口、AI 咨询、榜单、大厅卡片、会话制游玩（PvE/PvP）、模型托管——官方种子游戏（snake/tetris/microrts）与用户上传走完全同一条管线。包规范 v2 与完整步骤（模型契约、渲染、控件）见 docs/design/12/13 与 gdk-ug/。

my-game/

  __init__.py   # def get_adapter() -> EnvAdapter（info/new_state/step_state/validate_*/obs/ai_action…）
  weights.npz   # （可选）只读资源，.npz/.npy/.bin
# 本地自测：python gdk-ug/test_runner.py my-game
# 平台发布：官方包放 packaged-games/（启动自动播种）或用户经 /api/v1/ugc/games 上传审核

成长与排行 v1.0-c（XP/等级/统计/周榜）

数值见 docs/design/08-成长与赛事数值.md：PvP 对局结束 +10 XP、胜者额外 +15；PvE 完成 +5（胜利再 +5）；等级曲线 xp(n) = 50·n·(n-1)（L2=100）。每次 ELO 结算落 rating_history 一行供走势图。周榜 = 最近 7 天按胜场数聚合。

游玩会话 v1（服务器权威对局）

服务器持有权威状态；客户端提交动作推进 tick。创建会话需要登录账号（游客只能观战/看榜）。PvE 单人（可带服务端对手）；PvP 双人（邀请码、双方提交后推进、超时判负）。会话存于内存，空闲 30 分钟回收；每用户并发 8 局。提交动作可带 expected_tick，与服务端当前 tick 不一致返回 409（防网络重试双推进）。

POST /api/v1/{game}/play/sessions 创建/加入

PvE: {"kind":"pve","seed":42?,"opponent":{…}?,"controller":{…}?}
     opponent:   {"type":"ai","strategy":"light_rush"}          # 内置策略（microrts）
              |  {"type":"model","model_id":N}                  # 托管模型（登录）
              |  {"type":"external_bot","url":"https://…"}      # 你自己的 bot
     controller: {"type":"model","model_id":N}                  # 模型代打（snake/tetris，登录）
PvP: {"kind":"pvp"}                     # 创建房间（兼容默认 ranked + private）
     {"kind":"pvp","mode":"ranked|casual","visibility":"public|private"}?
     {"kind":"pvp","invite":"OD2ZX4"}   # 凭邀请码加入
→ {"session":{…},"invite":"OD2ZX4"?,"side":"p0|p1"?}

session 字段：id, game, kind, status, tick, state, winner, cause, opponent, invite, mode, visibility, players, p1_joined。status：waiting（PvP 等对手）→ active → finished（另有 abandoned/cancelled）。

房间 v1.0-a（公开大厅 / 邀请码双轨，06 M1）

房间 = waiting 状态 PvP 会话的正式化。公开房间出现在大厅列表，任何人可加入；私有房间凭邀请码加入。ranked 结算 ELO，casual 只落对局记录不计分（D10）。房间与队列均为内存态，服务重启即失效。

GET /api/v1/{game}/play/rooms 公开房间列表

GET /api/v1/microrts/play/rooms[?mode=ranked|casual]    # 需登录
→ {"rooms":[{"id":…,"game":…,"mode":"ranked|casual","visibility":"public",
           "invite":"OD2ZX4","host":"房主","host_id":N,"created_at":…},…]}
仅返回等待中的公开房间；5 秒轮询由前端驱动。

POST /api/v1/{game}/play/rooms 创建房间

{"mode":"casual|ranked","visibility":"public|private","settings":{"seed":N}?}
默认 casual + public（D10：练习局不计分）；private 房间仅凭邀请码加入。
→ {"session":{…},"invite":"OD2ZX4","side":"p0"}

POST /api/v1/{game}/play/rooms/{id}/join 加入房间

{"invite":"OD2ZX4"?}    # public 免码；private 必须携带正确邀请码（不区分大小写）
→ {"session":{…},"invite":"OD2ZX4","side":"p1"}
错误：404 房间不存在 · 400 邀请码无效 / 不能加入自己的房间 / 房间已满或已开始

快速匹配 v1.0-a（队列 + ELO band 撮合，06 §5 / D9）

每个 (game, mode) 一个内存队列；ranked 与 casual 分开撮合。ranked 撮合 band 初始 ±100，每 5 秒 +100 至 ±400，等满 60 秒任意对手；casual 不分差直接撮合。撮合即自动创建内部 PvP 房间（private，不进大厅列表，p0=先入队者），双方轮询 status 拿到房间 id 后进入对局。同账号不互配；同一对未打完不重复撮合；每人每游戏最多 1 个队列（重复入队=更新模式）；10 分钟无结果自动移出；队列内存态，重启失效。

POST /api/v1/{game}/matchmaking/queue 进入队列

{"mode":"ranked|casual"}   # 需登录；重复入队=更新参数
→ {"queued":true,"matched":false,"mode":"ranked","position":1,"wait_seconds":0,"session_id":null}
已撮合时直接返回 {"queued":false,"matched":true,"session_id":"…"}

GET /api/v1/{game}/matchmaking/status 排队状态（2s 轮询）

→ {"queued":true|false,"matched":true|false,"mode":…,"position":N,"wait_seconds":N,"session_id":…}
matched=true 时 session_id 为撮合出的房间 id（读取即消费该条目）；未排队时 queued=false

DELETE /api/v1/{game}/matchmaking/queue 取消排队

→ {"queued":false}    # 即时生效

断线重连 + 再来一局 v1.0-a（06 §7 U5/U7）

刷新/断线后凭 GET /api/v1/play/active 找回自己未完成的 waiting/active 会话（含阵营 side、tick）；对局结束后的 rematch 复制 settings/mode/visibility、互换 p0/p1 并开新房间把双方带回（幂等：双方各点一次进同一个新房间）。断线期间由现有超时策略兜底（60s 空过、连续 5 次判负）。

GET /api/v1/play/active 我的进行中对局

→ {"sessions":[{"id":…,"game":…,"kind":"pvp","status":"waiting|active",
              "tick":N,"side":"p0|p1","mode":…,"visibility":…,"players":[…],…},…]}
需登录；只含自己是参与者的会话（PvP 或本人 PvE），按最近活动排序

POST /api/v1/{game}/play/sessions/{id}/rematch 再来一局

→ {"session":{…新房间…},"invite":"…","side":"p0|p1"}
仅 finished 对局可用（400）；仅原双方可用（403）；先后手互换；
对已开过的 rematch 重复调用返回同一个新房间

观战 + 回放 v1.0-a（06 §7 U6 / 07 M4）

观战：GET /api/v1/{game}/play/sessions/{id} 非玩家返回 side:null（只读）。公开房间的对局与快速匹配撮合的对局任何人可围观；私有房间仅双方可读（403）。前端观战页 /watch/{game}/{sessionId} 2s 轮询、只读棋盘 + 双方提交指示。

回放：对局记录保存 game_version、seed、options 与 moves。回放器通过 OpenEnv 按原版本和初始化参数 reset，在同一 WS 连接逐条 step；渲染使用会话 environment.schemas/meta，完成/错误/取消均关闭连接。与 play 共用现有 EnvAdapter；分享链接 /watch/match/{id} 任何人可直接打开。缺版本、seed 或原包的历史记录不可用最新版猜测重建。

GET /api/v1/matches/{id}/replay 对局回放（公开只读）

→ {"replay":{"schema_version":1,"match_id":N,"game":…,"game_version":"1.0.0",
             "players":[{user_id,name,side}],"result":{winner,cause,damage,mode},
             "seed":N,"options":{},"moves":[
             {"tick":0,"action":{"p0":[…],"p1":[…]},"opponent":null},…]}}
无需登录；仅 finished 对局（PvE / PvP / model_vs_model）；旧记录可能缺版本或 seed

GET /api/v1/{game}/play/sessions/{sid} 查询/轮询

返回当前状态；PvP 下触发服务端超时策略（见下）。非玩家可读（观战视角 side:null）。

POST /api/v1/{game}/play/sessions/{sid}/actions 提交动作 → 推进 tick

{"actions": 0|1|2|3}                          # snake/tetris
{"actions": [[unit_id, cmd, dir?, type?], …]}  # microrts
{"actions": null}                              # 仅模型代打会话（服务器自己算）
{"actions": 1, "expected_tick": 7}             # 可选：乐观并发；不匹配 409（刷新后重试）

PvE 响应: {"state":{…},"tick":N,"done":false,"winner":null,"cause":null,
          "reward":0.0,"status":"active"}
PvP 响应: {"state":{…},"tick":N,"done":false,"advanced":false,
          "waiting_for":"p1","status":"active"}
          # advanced=true 表示双方指令到齐、本 tick 已推进

PvE 流程

  1. POST play/sessions {kind:"pve", opponent:{"type":"ai","strategy":"light_rush"}}（microrts；snake/tetris 不传 opponent）
  2. 循环：读 state → 决策 → POST actions → 拿新 state（服务端对手自动同步行动）
  3. done=true → 结束，响应带权威 match_id；用 POST /api/{game}/scores {"match_id":…} 领榜（分数由服务端从该对局读取，客户端不能自报）

PvP 流程（人 vs 人）

  1. 玩家 A：POST play/sessions {kind:"pvp"} → invite（6 位邀请码），side="p0"（蓝方），status=waiting
  2. 玩家 B：POST play/sessions {kind:"pvp","invite":"OD2ZX4"} → status=active，side="p1"（红方）
  3. 双方各自攒指令并 POST actions；一方提交后响应 waiting_for 指对方
  4. 双方都提交后服务器推进一 tick（advanced:true）；用 GET 轮询观察对手提交与推进
  5. 每步限时 60 秒：超时自动空过（players[].submitted 与 tick 会变化），连续 5 次超时判负；POST leave 认输 → 对方胜
  6. 结束后自动落库为对局记录；ranked 按 ELO（K=32，起始 1200）结算双方积分，casual 只落记录不计分（D10）
  7. 大厅流程：GET play/rooms 看公开房间 → POST play/rooms/{id}/join 直接加入（private 房凭邀请码）；同账号不可加入自己的房间

POST /api/v1/{game}/play/sessions/{sid}/leave 认输/退出

PvP 认输 → {"status":"finished","winner":1}   # 对方获胜；等待中的房间被创建者取消
PvE 退出 → {"status":"abandoned"}

GET /api/v1/{game}/play/sessions/{sid}/replay 回放

{"id":…,"game":…,"kind":…,"seed":…,"players":[…],"opponent":…,
 "moves":[{"tick":0,"action":…,"opponent":…},…],"result":{…}}

回放是每 tick 动作日志，可用环境 API 离线重放（同 seed 同轨迹）。

模型托管 v1（ONNX）

只接受 ONNX（onnxruntime CPU 推理）。上传时服务端校验：≤20MB、能加载、输入/输出 shape 匹配该游戏的标准契约；每游戏最多保留 5 个活跃模型。SDK 的 export_onnx 保证导出即合规。

契约游戏输入输出推理语义
game.snakesnakefloat32[1,1334] rotwin R=10 观测float32[1,3] Q 值simple：obs→argmax
game.tetristetrisfloat32[1,2,20,10] 双通道棋盘float32[1,4] Q 值simple：obs→argmax
game.micrortsmicrortsfloat32[1,1546] 6×16×16 网格 + 10 维单位特征float32[1,140] cmd×dir×type logitscomposite：model_inputs 逐单位 → 批量 run → model_decode（mask 后 argmax）

reset：固定版本与整局配置

{"type":"reset","data":{"seed":42,"version":"1.0.0","options":{},
                        "obs_mode":"state","rewards":{},"include_state":true}}
  • seed 为非负整数，默认 0；options 由游戏定义。
  • version 省略时使用当前发布版本；显式指定必须是仍可用的已审核包。reset 固定本局版本，发布/回滚不让进行中的局面换动力学；下架/暂停仍使会话不可用。SDK 默认持续钉住初始化时读取的版本。
  • obs_mode 缺省为首个服务端观测模式；显式 state 请求当前适配器完整状态，其他值必须由游戏声明。
  • rewards 只覆盖已声明奖励键，在整局内固定；值必须有限且绝对值不超过 1000。
  • include_state 默认 false，true 时张量观测也附带完整 state；非法配置明确报错。

step 与 observation

{"type":"step","data":{"value":1}}
→ {"type":"observation","data":{"observation":{…},"reward":0.0,"done":false,…}}

value 是游戏原始动作（整数、命令列表或复合对象），不含调用方注入的局面。reset/step 均返回官方 observation 响应，其中 observation 为：

# 张量观测；include_state=true 时 state 为完整局面
{"type":"tensor","data":[…],"shape":[…],"dtype":"float32","state":null,"metadata":{…}}
# 状态观测
{"type":"state","state":{…},"metadata":{…}}

reset 的 observation.metadata.environment 包含 game/name/actions/obs_modes/schemas/meta/version/max_concurrent_envs 等描述，step 不重复整份描述。完整状态是当前快照型适配器的能力，不要求所有未来游戏的策略观测公开内部状态。环境本身在 done 后不会自动 reset。

state 与网页/历史回放

{"type":"state"}
→ {"type":"state","data":{"episode_id":null,"step_count":0,"game_state":null,
    "environment":{"game":"tetris","version":"1.0.0","max_concurrent_envs":64,…}}}

reset 前 game_state=null，environment 描述当前版本；reset 后是本局状态与固定版本的 environment.schemas/meta。HTTP /schema 仅描述当前发布版本，不可替代历史包渲染配置。网页读取会话动作描述；游客预览 reset 获取初始状态后关闭连接，不创建 play Session。

回放记录仍来自平台业务 API；重建使用原 version + seed + options reset，再在同一连接逐条 step 记录动作，从返回状态渲染，最后关闭连接。确定性保证仅适用于固定版本、相同初始化参数与动作输入的当前游戏引擎，不扩展为任意外部引擎的 seed/快照支持。

游戏：俄罗斯方块 tetris

10×20 棋盘，7 种方块，7-bag 出块（由 (seed, bag_idx) 确定性生成，同 seed 同轨迹）。

state 字段说明
board20×10 整数矩阵：0=空，1..7=已锁定的方块 id+1
piece{"id":0..6,"rot":0..3,"x":int,"y":int}，当前活动方块

两种对战模式（由 OpenEnv reset 的 options.opponent 决定）

  • 单代理 vs 内置策略（默认）：opponent ∈ {worker_rush, light_rush, ranged_rush}——对方策略在服务端环境内部运行，API 动作只需提交己方（p0）的指令列表（与 snake/tetris 同构，SDK 零改动）
  • 双代理 external：opponent = "external"——API 动作为 {"p0": [cmds], "p1": [cmds]}，双方都由调用方控制（人机/机机对战，训练自对弈）。游玩会话（PvE/PvP）即此模式的服务端封装
  • obs（服务端）：grid = 6×16×16 通道（墙/金矿/我方单位/敌方单位/我方建筑/敌方建筑）
  • 奖励：{"win":1.0,"loss":-1.0,"damage":0.01}；每 tick reward = 本 tick 实际伤害×damage，终局 + win/loss（p0 视角）
  • 示例：连接 /api/openenv/microrts 的 GenericEnvClient，env.reset(seed=42, options={"opponent":"light_rush"}) 后，在同一连接 env.step({"value":[[0,5,1,"worker"]]}) 让基地向东产工人

自定义模型协议（🔌 挂自己的 bot）

游戏页面的「🔌 自定义模型」模式：填一个你自己的 HTTPS 服务 URL，游戏每步 POST 状态过去，按返回的动作走。你的模型在你自己机器上跑，平台只提供环境。也支持作为游玩会话的 external_bot 对手。

方向载荷
游戏 → 模型{"state": {…完整 state…}}（三个游戏通用）
模型 → 游戏（任选）snake/tetris：{"action": 0|1|2|3} / 裸数字；microrts：{"action": [[unit_id, cmd, dir?, type?], …]} / 裸指令列表

finally:
    envs.close()
