## 1. 产品定位（已确认）

**一句话：Stream 是 RL 实验室大厅。**

- **主卖**：训练闭环——OpenEnv / SDK 采样训练 → `export_onnx` → 平台托管（契约校验）→ 模型评估 / 模型对抗  
- **网页玩**：验证层——用同一套游戏引擎（EnvAdapter / 游戏包）核对动力学、演示与人工摸规则；**不是**对外主 CTA  
- **对战（房间 / 快速匹配 / ELO）**：验证与竞技支线；入口按游戏归属（`/games/{slug}/pvp`），不恢复独立对战中心  

与历史蓝图「游戏 + 训练 + 模型对战三位一体」的关系：能力仍三位一体，**对外叙事与 IA 主路径改为「训练/模型先行」**，玩与人机对战降为验证支线。

线上域名：`games.cree1p.com`。仓库总述见根 [`README.md`](../../README.md)。

## 2. 目标用户（主次已确认）

沿用蓝图 Personas，**主次重排**：

| 代号 | 角色 | 主次 | 核心诉求（产品侧） |
|---|---|---|---|
| **P3** | 模型作者 / 开发者 | **主** | OpenEnv 环境、SDK、ONNX 上传与契约、评估、模型 vs 模型、API 文档、游戏契约可读 |
| P1 | 休闲玩家 | 辅 | 登录后可玩 PvE（游客可看棋盘/榜）、内置 AI、分数榜、轻量摸规则（验证环境；2026-10-21 决策：对局必须登录） |
| P2 | 竞技玩家 | 辅 | 房间 / 快速匹配、ranked/casual、ELO、断线重连、再来一局 |
| P4 | 观战者 | 辅 | 观战链接、回放、分享 |
| P5 | 运营 / 管理员 | 辅 | 公告、封禁、模型/UGC 审核、看板、举报 |

## 3. 旅程

### 3.1 主旅程（第一天 / P3）

```
发现 API / Schema（大厅或 /api.html）
  → OpenEnv 连接 /api/openenv/{game}（或 SDK RemoteVecEnv / gym）
  → 本地训练（SB3/CleanRL 等）
  → export_onnx（契约）
  → 网页「模型托管」上传 → 评估
  → 模型挑战（vs 内置 AI / vs 其他模型）
  →（可选）网页玩或 PvP 验证手感与规则
```

### 3.2 验证支线

| 支线 | 路径概要 | 价值 |
|---|---|---|
| 网页单机 / PvE | `/games/{slug}` | 摸规则、人机演示、提交分数 |
| 人机 / 人对人 PvP | `/games/{slug}/pvp` | 房间、匹配、聊天、ELO |
| 观战回放 | `/watch/...` | 分享与复盘 |
| UGC 游戏包 | `/ugc` + 审核管线 | 扩环境供给（作者侧） |

### 3.3 与蓝图旧「第一天旅程」的差异

蓝图原文第一天偏「注册 → 选游戏 → PvE → 匹配 → 聊天 → 观战」。  
**现行产品决策**：第一天默认叙事改为训练闭环；旧旅程保留为 P1/P2 验收路径，不作为大厅主 CTA。

## 4. 成功指标草案（待运营校准）

| 层级 | 指标草案 | 说明 |
|---|---|---|
| 北极星（P3） | 周活跃「完成一次：上传或评估或模型挑战」的作者数 | 闭环是否真正被用 |
| 漏斗 | OpenEnv 连接 / SDK 调用 → 上传 ONNX → 评估完成 → 发起模型挑战 | 看卡在哪一环 |
| 验证层健康 | PvE 开局数、PvP 完赛率、回放打开率 | 验证层不能坏，但不抢主 CTA |
| 供给 | 公开游戏数（官方+UGC）、有 model 契约的游戏占比 | 环境与契约可读性 |
| 质量 | `/api/ready`、沙箱熔断次数、举报处理时延 | 平台可信 |

> 指标为 PM 草案；埋点与看板实现属 Backend / 运营，未在本轮改代码。

## 5. 非目标（本阶段）

- 恢复 `/arena` 或平行「对战中心」主导航  
- 把 Stream 叙事改回「纯棋牌大厅」  
- 在未确认规格前大改 `web/` 或破坏 OpenEnv 唯一环境入口
